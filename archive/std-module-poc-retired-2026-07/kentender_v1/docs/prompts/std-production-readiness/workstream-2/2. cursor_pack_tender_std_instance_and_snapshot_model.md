# 1. Implementation Mandate

Cursor must implement the Tender STD Instance and Snapshot Model exactly as specified.

The implementation is not a generic document management system.

The implementation is a legally defensible structured tender governance engine.

The implementation must enforce these principles:

1. STD Instances are Tender-bound.
2. STD Instances cannot exist without a Tender.
3. One Tender has exactly one current STD Instance.
4. Published STD state is immutable.
5. Addenda create new versions and snapshots.
6. Generated outputs are append-only versioned artifacts.
7. Downstream modules consume generated outputs by reference.
8. Manual downstream rule creation is prohibited.
9. Publication requires snapshots.
10. Audit history is append-only.
11. Readiness gates block invalid publication.

# 7. STD Instance State Machine

## Ticket STDINST-0120 — Implement Instance State Machine

### Objective

Implement deterministic lifecycle.

### Allowed Transitions

| From | To |
|---|---|
| Draft | In Configuration |
| In Configuration | Validation Blocked |
| Validation Blocked | In Configuration |
| In Configuration | Ready for Publication |
| Ready for Publication | Locked for Approval |
| Locked for Approval | Published Locked |
| Published Locked | Addendum Pending |
| Addendum Pending | Addendum Regenerated |
| Addendum Regenerated | Published Locked |
| Any non-final | Cancelled |
| Published Locked | Superseded |

### Prohibited Transitions

| Transition | Reason |
|---|---|
| Published Locked → In Configuration | Published immutability |
| Published Locked → Draft | Invalid rollback |
| Superseded → Active state | Historical object |

### Required Service

```text

```

### Acceptance Criteria

- Invalid transitions denied.
- State changes audited.
- Published immutability enforced.
