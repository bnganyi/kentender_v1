## 1. Implementation Mandate

Cursor must implement the Works tender-stage completion backend model exactly as specified.

This is not a document upload workflow.

This is the controlled completion of a structured Works STD Instance.

The implementation must ensure that a Works tender becomes publication-ready only after all required tender-specific STD data has been completed, validated, generated, snapshotted, and locked according to the legal rules of the STD Engine.

The implementation must enforce:

1. Works tender completion occurs only against a Tender-bound STD Instance.
2. The STD Instance must be derived from an active Works STD Template/Profile.
3. TDS and SCC are completed as parameter values, not edited clauses.
4. Evaluation/qualification inputs are limited to STD-defined parameterized thresholds/options.
5. Works Requirements are structured components, not arbitrary attachments.
6. Drawings are registered and section-bound to Section VII.
7. BOQ is structured and controlled by the Procuring Entity.
8. Supplier input is rate-only where applicable.
9. Arithmetic correction is Evaluation-stage only.
10. Bundle, DSM, DOM, DEM, and DCM must be generated and current before readiness passes.
11. Changes invalidate affected outputs.
12. Readiness blockers prevent lock for approval/publication.
13. Configuration snapshot is required before lock for approval.
14. All mutations and generation events are audited.
