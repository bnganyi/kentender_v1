## Rules of engagement (bench / KenTender)

These match how **previous modules** (e.g. Workstream 1, STD POC) were built:

1. **Architecture** — [`apps/kentender_v1/docs/architecture/kentender_architecture_rules_v3.md`](../../../../architecture/kentender_architecture_rules_v3.md), [`global-architecture-v3.md`](../../../../architecture/global-architecture-v3.md). **No new apps.** **`kentender_procurement`** owns procurement / tender management surfaces. **Business logic in `services/`**; DocType controllers thin; **explicit APIs** (`@frappe.whitelist` or documented service entrypoints).
2. **Workspace-first UX** — Landing → queue → detail → actions ([`apps/kentender_v1/AGENTS.md`](../../../AGENTS.md)); the pack’s “Official STD Library” is the target mental model, not a raw DocType workbench as the default entry.
3. **Spec and pack are law** — Doc **1** defines the product model and completion gate (§15). Doc **2** defines **STD-LIB-RULE-001–014**, selectors, ticket ids, API shapes, and **§28 implementation sequence**. Deviations belong in [`ISSUES_LOG.md`](ISSUES_LOG.md) with evidence.
4. **Governance integration** — Any flow that **imports, validates, activates, or supersedes** templates must **call or align with** existing governance services and server guards on **`STD Template`** ([`../workstream-1/`](../workstream-1/)); UI must not bypass `lifecycle_status`, hash evidence, or `allowed_for_tender_creation`.
5. **TDD; Playwright for Desk** — [`.cursor/rules/kentender-tdd-playwright-quality-gate.mdc`](../../../../../../.cursor/rules/kentender-tdd-playwright-quality-gate.mdc). Desk specs: [`.cursor/rules/frappe-desk-playwright-patterns.mdc`](../../../../../../.cursor/rules/frappe-desk-playwright-patterns.mdc); reuse [`apps/kentender_v1/tests/ui/helpers/deskForm.ts`](../../../tests/ui/helpers/deskForm.ts) where applicable. **Done** on this UI requires automated tests **or** a logged environment blocker.
6. **Bench / Node** — From bench root use [`./scripts/bench-with-node.sh`](../../../../../../scripts/bench-with-node.sh) for any `bench build` touching `public/js` / `public/css` per [`.cursor/rules/frappe-bench-node.mdc`](../../../../../../.cursor/rules/frappe-bench-node.mdc). **Do not** use plain `bench build` in agent terminals.
7. **Site** — Prefer **`bench --site kentender.midas.com`** for site-scoped commands ([`AGENTS.md`](../../../../../../AGENTS.md)).
8. **Regression** — After touching **`STD Template`**, loader, or engine, run targeted `kentender_procurement` tests: at minimum `test_std_works_poc_step9_doctypes`, `test_std_works_poc_step10_loader`, `test_std_works_poc_step11_engine`, and relevant `test_std_template_governance*` / smoke modules unless a deviation is recorded.
9. **Reference display** — Where the UI shows catalogue or links, follow [`.cursor/rules/kentender-dropdown-reference-standard.mdc`](../../../../../../.cursor/rules/kentender-dropdown-reference-standard.mdc) (business-facing **name + code**, not raw internal ids in primary labels).

**Implementation surface note:** Doc 2 describes **`/desk/std-engine`** and example **`frontend/src/.../stdLibraryApi.ts`** paths. **This bench is Frappe Desk–first.** The default delivery is expected to be **Desk Page(s), workspace shortcuts, and/or `public/js`** under `kentender_procurement`, with pack REST shapes implemented as **whitelisted methods** or dedicated API modules—not a separate SPA—unless **§A** records an explicit product decision to add a SPA. Map pack selectors to **data-testid** / stable hooks in the chosen stack.

**Pack role / permission names** (`ROLE_STD_ADMIN`, `PERM_TEMPLATE_*`) are **conceptual**. Map to existing **Frappe Role / DocPerm** (`STD Template Administrator`, `STD Technical Inspector`, etc.) and **server-side** checks; record mapping in **§A** or [`ISSUES_LOG.md`](ISSUES_LOG.md).

**Status values:** `Not started` | `In progress` | `Partial` | `Blocked` | `Done`
