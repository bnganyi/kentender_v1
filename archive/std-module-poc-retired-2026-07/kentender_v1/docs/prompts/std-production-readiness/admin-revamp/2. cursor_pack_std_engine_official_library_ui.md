## 1. Implementation Mandate

Cursor must implement the **Official STD Library UI** as the primary STD Administrator interface.

The UI must stop presenting the STD Engine as a low-level configuration console. It must instead present official standard tender documents as controlled library assets that are imported, validated, previewed, activated, reused, and occasionally superseded.

The administrator must not be asked to manage raw internal data structures during normal operation.

The implementation must enforce these principles:

1. The default view is an official STD library, not a mapping console.
2. The normal onboarding path is **Import Official STD Package**, not manual construction from scratch.
3. A raw PDF or Word file is source evidence only; it does not become the runtime rule source by itself.
4. Validation is central and must be presented as health checks, not raw errors.
5. Bundle Preview is central and must show the recombined tender document output.
6. Advanced technical configuration exists but is hidden by default.
7. STD Instances are not created or edited in this UI.
8. Active STD versions are immutable.
9. Supersession is explicit and versioned.
10. All mutation actions must be permission-checked by backend action availability.
11. The previous engine-facing UI must be suppressed or moved under Advanced Technical View.

## 5. Roles and Permissions

```text
ROLE_STD_ADMIN
```

### 5.2 Required Permission Mapping

| UI Action | Required Permission |
|---|---|
| View Official STD Library | PERM_TEMPLATE_VIEW |
| Import Official STD Package | PERM_TEMPLATE_CREATE |
| Register Source Document | PERM_TEMPLATE_CREATE |
| Validate Imported Package | PERM_TEMPLATE_RUN_VALIDATION |
| Submit for Review | PERM_TEMPLATE_SUBMIT_REVIEW |
| Activate Template Version | PERM_TEMPLATE_ACTIVATE, if STD Admin is permitted in final governance; otherwise hide from STD Admin |
| Create New Revision | PERM_TEMPLATE_CREATE |
| Open Advanced Technical View | PERM_TEMPLATE_EDIT_STRUCTURE or PERM_TEMPLATE_CONFIGURE_MAPPINGS |
| Edit Advanced Technical Configuration | PERM_TEMPLATE_EDIT_STRUCTURE / PERM_TEMPLATE_CONFIGURE_MAPPINGS / relevant granular permission |
| View Audit Trail | PERM_TEMPLATE_VIEW or PERM_AUDIT_VIEW |
| Export Evidence | PERM_AUDIT_EXPORT, if available |

### 5.3 Permission Enforcement Rule

The frontend must never decide final permission alone.

Every mutation action must call or consume:

```text
GET /api/std-engine/action-availability
```

or equivalent backend service.

The action availability response must include:

```json
{
  "action_code": "IMPORT_OFFICIAL_STD_PACKAGE",
  "allowed": true,
  "denial_code": null,
  "message": "Allowed",
  "requires_confirmation": false,
  "risk_level": "High"
}
```

If denied:

```json
{
  "action_code": "IMPORT_OFFICIAL_STD_PACKAGE",
  "allowed": false,
  "denial_code": "STD_AUTH_PERMISSION_DENIED",
  "message": "You do not have permission to import official STD packages.",
  "requires_confirmation": false,
  "risk_level": "High"
}
```
