## How to read this table

- **Today** is what the code decides now. **Change** is the smallest edit that delivers the OVS v0.6 §4.1 row. **Not changed** states what must stay.
- A read grant is not an action grant. No row adds a command, task or approval (OVS-AC-007, OVS-AC-011).
- "Department head" means the Head of User Department responsibility, which is Organisation Unit scoped (AUTH-ADR-001 v1.11 §4.4).
- Phase column: where the row is built. Phases 2–4 are the first slice; Phase 10 is the other-module reads.

## Cross-cutting rules every row obeys

- Scope is resolved by the existing responsibility registry and the registered predicates, matching each valid role-and-scope pair with no Cartesian expansion (AUTH-ADR-001 v1.11 §5.3). The resolver is `kentender_core/kentender_core/services/authorization.py`: `permitted_ou_scopes` (212), `descendants_of` (239), `report_match_conditions` (495).
- Tender lead and contributor scope comes from the Tender's immutable source handoff, not a new Frappe User Permission (OVS impact schedule, AUTH-ADR-001 row).
- Rows, totals, evidence and search suggestions use identical scope.
- A grant never depends on a URL or an office label alone (OVS v0.6 §4.1, last paragraph).
- Existing valid access is retained (OVS v0.6 §4.1: "All existing valid access is retained.").
