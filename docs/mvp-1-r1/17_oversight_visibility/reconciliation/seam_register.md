# OVS-CHG-001 v0.6: seam register (Phase 0, OVS6-0004)

A seam is a place where one owner reads or calls another. Each row names the producer, the consumer, the concrete function or hook that exists today (checked in `kentender_procurement/kentender_procurement/` on 4 October 2026), the gap, and the phase that closes it. "Dependency direction" in `CLAUDE.md` is `procurement planning → tenders → opening → evaluation → award`; a read that runs against it goes through a published hook, never a deep import.

## Direction check

- S1 and S6 point from downstream owners up to Tenders and Proceedings through hooks. Neither Tenders nor the register imports an owner's tables.
- S3 is the only seam that runs against the dependency direction (Evaluation asking Award). It goes through Tenders' existing `evaluation_seam`, which already does this for the decision status, and returns data, not records.
- S2 and S5 are reads inside one owner.

## Checked and found not needed

- No new doctype and no new stored field is required by any seam above. The only possible exception is the evidence association under D3, which is conditional and needs the owner's sign-off first (FU-OVS-11).
