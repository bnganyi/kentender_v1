## Tracker rules

1. **Rows are permanent.** Status vocabulary: `Planned` / `In progress` / `Blocked` / `Blocked — owner` / `Partial` / `Done`. Reversed decisions are struck through in place, never deleted.
2. **`Done` needs the row's own evidence:** a command with result counts, a named test, a commit, or a described browser observation with the literal rendered strings. Never record a result that was not observed. A passing narrow test does not close a row whose acceptance criterion is broader.
3. **A UI row closes only after the live check** on the running site, as the named persona, from the menu or the Tender record, not by address alone. Record "tested by address" otherwise.
4. **Test site only.** Python and browser tests run on `kentender-test.local` through `scripts/test-site.sh`. Never run Python tests while a Playwright process is active. Check `make ui-queue-check` before reading code on an odd UI failure.
5. **Reads create nothing.** A row is not Done if opening an oversight view creates a business event, clears a task or sends a notification (OVS-AC-011).
6. **No stored field without the owner.** OVS v0.6 §3: "Every stored extension must have a demonstrated gap and named consumer." Any storage addition (for example the D3 evidence association) is a follow-up with owner sign-off before it is built.
7. **Approved documents are not edited.** A defect found in a filed document is a row in the follow-ups file. Treat each document's top "Controlling approval" paragraph as winning over its older proposal wording.
8. **Cross-app callers.** Before removing or reshaping a hook, read or role tuple, grep the whole repository for real callers, not only the owning module (Phases 3, 10, 12).
9. **Design gate.** No UI row (Phases 6–8) is Done before Gate OVS-G01. Server rows do not wait.
10. **Disclosure is tested end to end.** A disclosure row needs a negative case driven through the real endpoint as the real persona (Amina Hassan, Charles Mutiso, Naomi Chebet, Dr Peter Kimani), including the direct file download.
11. **Narrow then broad.** Red then green on one test, the module tests once, then broaden only at a gate. Do not rerun hundreds of tests after a small edit. Fidelity gates are due once per slice.
12. **Fixtures clean up.** Every test module registers a purge cleanup; browser-pass records count as test data; `setUpClass` fixtures that commit survive rollback. Reseed the canonical world after a run that persists.
13. **Deferred scope stays deferred.** Contract Management, the template walkthrough and supplier contract/delivery/payment designs stay `Blocked — owner` and count toward no readiness claim (OVS v0.6 §17).
14. **No completion claim while a coverage row is open.** OVS is not "implemented" until every Phase 11 coverage row has a result or a reasoned exclusion.
15. **Report exactly what was and was not run.** Never claim a result that was not observed.
16. **Commits only when the owner asks.**
