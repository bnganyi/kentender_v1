## 1. Governing approach

**Rebuild, not patch.** v0.8 removes concepts the v0.6 build was organised around (a separate "Tender Preparation" module, a `TenderPublicationHandoff`, five preparation tasks, the `TPR_*` error set, publication as another module's concern) and adds an entire second half (publication authorisation, channel confirmation with evidence, addenda, inquiries, cancellation, submission close). Per `feedback-rebuild-vs-patch-threshold` that is a rebuild. The new module is `kentender_procurement/kentender_procurement/tenders/` ("Tenders"), one Frappe Page `tenders`, one Vue app. Nothing is imported from the retired module; proven mechanics are re-established by copying the Requisitions module's patterns by diff (`envelope` idempotency journal with named savepoints, closed error set, explicit-signature `api.py` with AST guard, verdict-first workspace read, one `kentender_core.desk_page.register()` controller, shared rail via `mountPageRail`, per-slice Make gates, one Playwright world with one reset function per spec, design-fidelity spec against the board files).

**Order of work is the spec's own §15.1**: schemas and authority → commands and audit → deterministic documents → evidence and publication → reads and tasks → artboards → release verification. Phases 2–6 are horizontal (Python only, TDD per behaviour). Phase 7 is vertical per board: API adapter → screen → live browser check → fidelity assertion → next board (`feedback-rebuild-phase-sequencing`).

**Done means the §13.3 primary lifecycle completes in a browser as real actors.** Brian Wafula starts, prepares and submits; Charles Mutiso returns then approves; Amina Hassan authorises publication; Charles confirms four channels with evidence and attestation; the Tender becomes Published — open with `published_at` 15 May 2027 08:00 EAT and one Planning invitation actual; Charles issues and fully publishes the addendum; Brian answers the inquiry; the submission period closes and one immutable Bid Submission handoff exists. Every §13.4 isolated fixture is proven in the test world.

Non-negotiables inherited from AGENTS.md: business rules in services, never in Vue; every command re-checks responsibility, state, segregation and record version on the server; no `frappe.db.commit()` in request services; Industry only, boards ported class-for-class with the machine-enforced fidelity gate; `frappeCall` `silent: true`; inline errors never Message dialogs; Python suite and Playwright never run together on the site; every test module registers a purge; the two ideas the retired module's follow-ups already proved are kept as rules (see §3).
