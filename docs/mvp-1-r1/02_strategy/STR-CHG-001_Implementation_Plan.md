## 1. Governing approach

**Correct in place; re-port every Strategy screen from the v1.8 artboards; re-tune the shared design system once.** v1.8 removes no domain concept (§1.1 reopens nothing), so by the rebuild-versus-patch threshold this is a patch cycle: the four-state lifecycle, six commands, four consumer contracts, 20 business rules, the one Desk Page and the proven `SELECT … FOR UPDATE` overlap guard all stay. What changes is composition, vocabulary, command orchestration on the client, the comparison service, idempotent replay on the write commands, the fixture profiles, and the design system the whole product renders on.

**Phase ordering follows the retrospectives.** Phase 1 is horizontal and shared (the design system every Industry page reads). Phase 2 is horizontal within Strategy (server read/command contracts, comparison, readiness, replay, fixtures) so every screen phase consumes finished contracts. Phases 3A–3E are vertical, one route family at a time: API read model → screen port → Playwright with per-role logins → live click-through. Phase 4 is the release gate.

**Done means the §14 actors complete the §16.2 (12) journeys in a browser** on the v1.8 compositions: Esther creates a plan and adds objectives, updates the current plan, edits structure with one Save changes and submits; Alfred reviews the decision overview first, returns once with the §11.9 reason, and approves the corrected immediate-effective submission; Naomi reads; Administrator reads every status read-only; Samuel is refused inline with no disclosure; the July-2027-effective profile is refused in November 2026.

Non-negotiables restated from AGENTS.md and KT-STD-001 v1.5: business rules in services, never in Vue; every command re-checks responsibility, state and record version on the server; artboards ported class-for-class; verdict before paint and Forbidden-as-data (§3A); inline errors never Message dialogs; the Python suite and Playwright never run concurrently on the site; TDD per behaviour; report only what was observed.
