## Tracker rules

1. Rows are permanent and use `Planned`, `In progress`, `Blocked`, `Done`.
2. `Done` requires the row's own evidence (a command, a test name, a diff) — not "looks right."
3. If a rebuilt/edited file still references the open `UOM` Link for item units, a 3-digit reference format, or the workspace's placeholder-toast row actions, the row that touches it is not Done.
4. No row may introduce a compatibility shim, dual field (old + new), or feature flag. A confirm-not-rename decision (Phase 1/5) must be recorded as a decision with reasoning, not silently skipped.
5. Every phase's closing verification must reproduce the Phase 0 baseline's non-Departmental-Needs-caused failures (if any) unchanged — this module's tests are expected to be clean or near-clean already (`06_...Tracker.md` RBD-G05), so any new non-passing test after Phase 0 is presumed a regression until proven otherwise.
6. HTML mockups (`NDS-UI-02[A|B|C].html`) are illustrative Stitch references; the MD spec's §7 tables are the authoritative fixture content when the two disagree (already found once: `NDS-UI-02B.html` is missing its footer actions entirely — build against the MD table, not the incomplete HTML).

### Real bugs found and fixed during Phase 6 live verification

Beyond the seed gaps noted in NDC-602/603, exercising the new screens end-to-end (not just checking they render) surfaced defects that a render-only check would have missed entirely:

1. **Frappe-core routing pitfall** (`departmental_needs_create_page.js`): both `departmental-needs-new` and `departmental-needs-edit` share one controller file, registered via `["departmental-needs-new", "departmental-needs-edit"].forEach(name => { frappe.pages[name] = frappe.pages[name] || {}; ... })`. Since Frappe's `pageview.show()` only calls `new frappe.views.Page(name)` (which creates the actual wrapper/container) when `frappe.pages[name]` is falsy, visiting either page first pre-populates the *other* name's `frappe.pages` entry as an inert stub — so navigating to it afterward via `frappe.set_route()` (as every real in-app button click does) rendered a permanently blank page. Fixed by only attaching handlers when `frappe.pages[name]` already resolves to a real wrapper (`if (!frappe.pages[name]) return;`), letting Frappe create the wrapper properly on each name's genuine first visit.
2. **`frappe.set_route(name, {key})` does not append a query string** — confirmed by reading Frappe's own `router.js`: the value is carried only through `frappe.route_options`, and `push_state()` never appends the computed query string to the URL. All 4 pages' `need` param resolution was fixed to prefer `frappe.route_options.need` (deleting it after read) and fall back to the URL query string for direct/bookmarked navigation.
3. **`doSave()` always redirected via `frappe.set_route`**, even when already on the edit page for an existing Need — combined with bug 2, this silently dropped `?need=...` from the URL on every "Save changes" click, so a page reload afterward had nothing to reload against. Fixed to only navigate on the first save of a new draft (create→edit transition); subsequent saves while already in edit mode just update state and show the toast.
4. **`repaintForm()` stripped the root `data-testid`/`kt-nds-root` element on every re-render** (add item, remove item, change an item's unit) — `$body.html(jQuery(formMarkup(state)).html())` parses the markup string into an element and reads back only *its children*, discarding the root wrapper itself, silently removing both the test hook and the CSS scoping class from the live DOM after the very first interactive edit. Fixed to `$body.html(formMarkup(state))` (no intermediate `jQuery(...).html()` unwrap).

All 4 were found only because NDC-607's Playwright specs drive real click-through navigation and interactive edits rather than checking each screen in isolation via direct URL — confirming the value of the "no approximations" testing standard for this phase.
