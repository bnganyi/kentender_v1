## 1. Closure decision

Gate 1 is closed at requirements level for the supported MVP slice: straightforward off-the-shelf IT Goods, Open Tender, single lot, KES, fixed price, public Tender discovery, Tender-bound candidate registration, STD-driven bid preparation and sealed electronic submission.

There is no separate **Declare interest** or **Follow Tender** step. **Start bid** atomically creates or returns the Tender-bound candidate registration, mandatory-notice address and Bid Workspace. General pre-bid questions are supported before the clarification deadline. Tenders owns the authoritative clarification, answer, candidate audience, notice and delivery evidence; Bid Submission owns the candidate relationship and verified notice contact. Configuration owns one allowlisted public support/legal-link projection. The template bundle owns only reusable Tender/document/response/mapping assets and addendum identity rules.

Gate 1 requirements closure is not production go-live approval. Production submission remains disabled by default until the exact signing, trusted-time, encryption, sealed-custody, backup/recovery and incident operating profile has approved implementation and verification evidence.

## 4. Streamlined implementation order

1. Approve STD-TPL-001 v0.10 and STD-TPL-IMP-001 v1.0; implement immutable registry/assets, structured gates, change report, shared compiler and renderer adapters.
2. Reconcile and rebuild release 1.1; rerun the complete validator, generate the exact manifest/change report and obtain exact-manifest approval.
3. Implement **STD Templates** projections, coverage/change inspection, concern capture and bounded permissions before relying on it for diagnostics.
4. Implement TPR v0.11 binding/lifecycle enforcement, clarification, candidate-audience, outbox and delivery evidence.
5. Implement CFG v0.16 `PublicPortalSettings`, owner commands, public projection and C05 UI.
6. Implement BDS v0.7 atomic Start bid, notice-contact selection and TPR clarification/notice consumers.
7. Generate the five-task Bid Workspace only from the exact effective Published Bid Definition; remove hard-coded, PDF-derived or addendum-only paths.
8. Implement central submission availability, signature/package/deposit/receipt paths and keep the production flag false.
9. Run changed-contract tests, then the deterministic integrated fixture through sealed handoff.
10. Enable production submission only after the separate operating-profile, security, custody and recovery evidence is approved.

Design and code may proceed in parallel only after the owner contracts in steps 1–4 are fixed. Design must use KT-STD-001 v1.8 §2 plus the complete static-design section of the owning module; it must not infer missing fields from another module or from raw JSON.
