## Tracker rules

1. Rows are permanent and use `Planned`, `In progress`, `Blocked`, `Done`.
2. `Done` requires the row's own evidence (a command, a test name, a diff) — not "looks right."
3. If a corrected file still imports or references a removed concept (Budget Line Value Treatment, the Administrator/PE-MOH fallback, the stale `BUD-FR-062–066`/pre-BUD-CHG-001 UI numbering), the row that touches it is not Done.
4. No row may introduce a new alias, redirect, dual read, shadow write, or feature flag. If one appears, treat it as a defect in that row, not a valid completion.
5. Several rows (BCL-301, BCL-403/404, BCL-601, BCL-701–703) depend on a direct code read this audit deliberately did not resolve (see `01_...Audit_Report.md` §3/§6/§9). Do not mark these `Done` on the audit's inference alone — confirm against the actual function body first.
