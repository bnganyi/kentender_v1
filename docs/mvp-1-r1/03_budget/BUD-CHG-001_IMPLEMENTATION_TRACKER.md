## Tracker rules

1. Rows are permanent. Vocabulary: `Planned` / `In progress` / `Blocked` / `Partial` / `Done`. Reversed decisions are struck through in place.
2. `Done` requires the row's own evidence: a command with result counts, a named test, a diff, or a described browser observation with literal rendered strings. Never record a result that was not observed.
3. §11 governs visual/content fidelity only; §12 governs behaviour; §13 governs error copy.
4. No alias, redirect, dual-write, compatibility shim or parallel surface. Old labels (Current floor, Headroom, Owner scope, Authorised total on screens, Create revision, Register approved budget, Entity-wide as a label) are replaced, not kept as fallbacks.
5. Every visible action maps to one existing §9.2 command; no new command, status, role, queue or approval stage.
6. Never run the Python suite while a Budget Playwright process is active on the site.
