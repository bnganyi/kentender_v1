## Tracker rules

1. Rows are permanent. Vocabulary: `Planned` / `In progress` / `Blocked` / `Done`. Reversed decisions are struck through in place.
2. `Done` requires the row's own evidence: a command with result counts, a named test, a diff, or a described browser observation with literal rendered strings. Never record a result that was not observed.
3. A row touching a file that still references a spec-prohibited concept is not `Done`. Prohibited here: `pe_fy_context`, `procuring_entity` as a Requisition field or argument, a Fiscal Year or Procuring Entity scope argument on any command, `User Permission` as authority, native Frappe Role as authority, STD `manifest` / `composer` / `capability_profile` / schema or mapping objects, an attachment-primary specification, `Requisitioner` / `Business Approver` / `Procurement Approval Authority` and the other v1.2 role names, a technical-review / Finance / Accounting Officer / committee stage, Stitch or Civic Ledger markup, `kt_cl_surface_registry.js` entries, a sidebar work-queue entry.
4. No row may introduce an alias, redirect, dual-write, compatibility shim or parallel legacy+new surface. Deletion lands in the same phase as its replacement.
5. Screens are built from `REQ-CHG-001 Artboards.dc.html` class-for-class; behaviour from §14, never from artboard content. Reusing a component for a screen whose artboard differs means re-porting it.
6. Slice gates (REQ-G03..G09) close only on the plan's §4 slice gate: component tests, fidelity assertions per artboard, a Playwright spec on the D13 world with per-role logins (each §8 actor served plus one outsider and one unassigned user), absence assertions on refusal paths, first paint **and** one interactive re-render observed live, direct load / reload / back-forward, a forced 500 state, the inline-error check, zero page-specific console errors, bundle hash changed.
7. Static and architecture guards are `Done` only when proven by a planted violation.
8. Fixture instants are pinned, never `now`-relative; the Python suite and Playwright never run concurrently on the site. A row claiming a cross-app file is unaffected cites the specific file:line checked.
9. Diagnosis follows the KT-STD-001 §5 ladder; a full-suite run is never the first diagnostic step. A phase overrunning its target by half stops and records why.
