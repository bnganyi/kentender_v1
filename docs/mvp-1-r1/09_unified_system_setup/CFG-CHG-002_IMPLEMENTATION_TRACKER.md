## Tracker rules

1. Rows are permanent. Vocabulary: `Planned` / `In progress` / `Blocked` / `Partial` / `Done`. Reversed decisions are struck through in place.
2. `Done` requires the row's own evidence: a command with result counts, a named test, a diff, or a described browser observation with literal rendered strings. Never record a result that was not observed.
3. §10–§10.12 governs visual/content fidelity; §11 governs behaviour; §8/§8.1 governs error/readiness copy.
4. No alias, redirect, dual-write, compatibility shim or parallel surface. The monolithic `Regulatory Reference` doctype is retired once its data is migrated into the new envelope (D1), not kept as a fallback.
5. Every visible action maps to one existing §7.1 command; no new command, status, role, queue or approval stage beyond §7.1's table.
6. Never run the Python suite while a System setup Playwright process is active on the site.
