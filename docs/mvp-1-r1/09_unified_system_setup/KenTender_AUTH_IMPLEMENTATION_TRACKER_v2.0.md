## Tracker rules

1. Rows are permanent and use `Planned`, `In progress`, `Blocked`, `Done`.
2. `Done` requires the row's own evidence — a command with its result, a named test,
   a diff, or a described browser observation. A result that was not observed is
   never recorded.
3. A row that leaves production code reading a retired authority store (Frappe
   `User Permission` as KenTender authority, `User Scope Assignment`,
   `Capability Profile`, `Operational Scope Assignment`, `kt_primary_department`,
   browser context) is not `Done`.
4. Deletion lands in the same phase as its replacement, **except** where D2 defers a
   physical drop behind a live downstream reader — that deferral must be recorded on
   the row and closed in the removal phase.
5. No fallback chain: a caller flips onto the new mechanism exactly once (ADR §11.5).
6. Test suites purge their own data (standing Project Owner rule, 2026-09-01);
   browser-created records count as test data.
