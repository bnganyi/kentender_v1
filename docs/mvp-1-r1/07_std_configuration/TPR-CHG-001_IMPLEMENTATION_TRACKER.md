## Tracker rules

1. Rows are permanent. Vocabulary: `Planned` / `In progress` / `Blocked` / `Done`. Reversed decisions are struck through in place.
2. `Done` requires the row's own evidence: a command with result counts, a named test, a diff, or a described browser observation with literal rendered strings. Never record a result that was not observed.
3. A row touching a file that still references a spec-prohibited concept is not `Done`. Prohibited here: `pe_fy_context`, a Procuring Entity or Fiscal Year scope argument on any command, `User Permission` as authority, a native Frappe Role as authority, the literal `Procurement Tender`, STD `manifest` / `composer` / `capability_profile` / schema, clause or mapping editor objects, a template selector, an attachment-primary technical specification, `TPR_ROLE_REQUIRED` / `TPR_SCOPE_DENIED`, any `bid_opening` actual, a Tender reviewer / technical approver / committee / publication approver stage, Stitch or Civic Ledger markup, `kt_cl_surface_registry.js` entries, a sidebar work-queue entry, `showPeSwitcher: true`.
4. No row may introduce an alias, redirect, dual-write, compatibility shim or parallel legacy+new surface. Deletion lands in the same phase as its replacement. The legacy `tender_configurations/`, `tender_management/` and `std_configuration/` packages are neither called, extended nor deleted in this cycle.
5. Screens are built from `design/Tender Preparation Screens.dc.html` class-for-class, one `<section id>` per screen; behaviour from §14, never from artboard content. Reusing a component for a screen whose artboard differs means re-porting it.
6. Slice gates (TPR-G05..G10) close only on the plan's §4 slice gate: component tests, a fidelity assertion per artboard section, a Playwright spec on the D15 world with per-role logins (officer, HoPF, `both`, auditor as §5 allows, plus outsider and nobody refused), absence assertions on refusal paths, first paint **and** one interactive re-render observed live, direct load / reload / back-forward, a forced 500 state, the inline-error check, zero page-specific console errors, bundle hash changed.
7. Static and architecture guards are `Done` only when proven by a planted violation.
8. Fixture instants are pinned (§16.2, KT-STD-001 §8.4A: 20 Mar 2027 – 15 May 2027 EAT), never `now`-relative; the Python suite and Playwright never run concurrently on the site. A row claiming a cross-app file is unaffected cites the specific file:line checked.
9. Diagnosis follows the KT-STD-001 §5 ladder; a full-suite run is never the first diagnostic step. A phase overrunning its target by half stops and records why. Gate TPR-G01 (template 1.1 owner approval) is a hard human stop: Phase 3 and every render-dependent test wait for it.
