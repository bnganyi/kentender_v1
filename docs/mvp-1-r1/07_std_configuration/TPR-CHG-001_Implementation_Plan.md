## 1. Governing approach

**Greenfield build that mirrors Procurement Requisitions one-for-one.** Nothing exists to correct; the risk is invention. Every structural choice is a copy of the REQ-CHG-001 v1.6 build (`procurement_requisitions/`): the module layout, the `envelope` idempotency journal with named savepoints, the closed error set, the explicit-signature `api.py` with its AST guard, the verdict-first workspace read, the one-`register()` page controller, the shared route/rail adapters, the per-slice Make gate, the one-world Playwright fixture module with one reset function per spec file, and the design-fidelity spec against the artboard file. The template bundle is a plain Python package (`tender_templates/`: loader, registry, renderer); its one doctype `Supported Tender Template` belongs to the "Tender Preparation" module.

**Done means the officer journey completes in a browser as real actors.** Brian Wafula (Procurement Officer) prepares the IT Goods Tender from the authorised Ministry of Health handoff using the installed `IT-EQUIPMENT-OPEN-V1` version 1.1 bundle, completes the five tasks, runs readiness and submits; Charles Mutiso (Head of Procurement Function) returns once and then approves; one immutable `TenderPublicationHandoff v1.1` exists afterwards. Publication acknowledgment and the milestone write-back are Python services proven by tests plus one System-Manager-only technical endpoint used by smoke only.

Non-negotiables inherited from AGENTS.md: business rules in services, never in Vue; every command re-checks responsibility, state and record version on the server; no `frappe.db.commit()` in request services; artboards ported class-for-class with machine-enforced fidelity; `frappeCall` `silent: true`; inline errors never Message dialogs; the Python suite and Playwright never run concurrently on the site; TDD per behaviour.
