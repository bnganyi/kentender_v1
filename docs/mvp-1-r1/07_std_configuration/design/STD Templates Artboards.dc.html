STD Templates — static design artboards

Built from KT-STD-001 v1.8 §2 and STD-TPL-001 v0.10 (revised) §11 only. Desktop web only, 1440 wide. Artboards start below the Frappe Desk header, so there is no breadcrumb, shell or sidebar inside them. Fixture context (actor, time, route) sits in each label, not in the artboard.

Next step stated once. STD-DES-02 keeps the consequence sentence and puts the next-step headline straight after it as plain text with no container (it fits "Waiting on someone", §2.9.1). The duplicate "…must complete the checks below" wording is removed (§2.9.3 rule 1). No person or "since" time is drawn because none is supplied.
Blockers listed once. They are Level 1 in §11.3, so the ordered list with its owner sits at the top. Verification carries the eight checks and points back to it (§2.9.3 rule 2).
Status hues. Available = live, Unavailable / Incomplete = attention, Superseded / Pending = pending, Withdrawn / Failed = critical. Text always carries the state.
KT-STD over DS where they differ. Table headers are set in sentence case (§2.6.7), not the design system's uppercase. The DS app shell is not used (§2.2, §2.4). The design system's cool ground stands in for "warm-white" (§2.4); owner to confirm.
Values not supplied. Where a variant needs a value the snapshot doesn't supply, a dashed slot names the projection field. It is review markup, not product copy.
Disclosures. View coverage details and View change details stay closed because no row data is supplied. Technical details opens on STD-DES-02 (click it) and shows "Not recorded" for every value.
