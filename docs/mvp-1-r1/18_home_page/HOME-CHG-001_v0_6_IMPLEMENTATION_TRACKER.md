## Tracker rules

1. **Rows are permanent.** Status vocabulary: `Planned` / `In progress` / `Blocked` / `Blocked — owner` / `Partial` / `Done`. Reversed decisions are struck through in place, never deleted.
2. **`Done` needs the row's own evidence:** a command with result counts, a named test, a commit, or a described browser observation with the literal rendered strings. Never record a result that was not observed. A passing narrow test does not close a row whose acceptance criterion is broader.
3. **A UI row closes only after the live check** on the running site, as the named persona, from the sidebar or the bell, not by address alone. Record "tested by address" otherwise.
4. **Test site only.** Python and browser tests run on `kentender-test.local` through `scripts/test-site.sh`. Never run Python tests while a Playwright process is active. Check `make ui-queue-check` before reading code on an odd UI failure.
5. **Reads create nothing.** A row is not Done if loading, paging, retrying or navigating from Home creates a business event, clears or marks read a task, or sends a notification (HOME-AC-03).
6. **No stored field and no owner workflow change.** An owner feed reshapes existing owner data; it adds no task, decision, DocType or stored business field. Any storage need is a follow-up with owner sign-off before it is built.
7. **Approved documents are not edited.** A defect found in a filed document is a row in the follow-ups file. Document changes (SEED-OPS v1.25, register entries) follow the kentender-document-change protocol, and the latest version is checked first.
8. **Cross-app callers.** Before reshaping a hook, boot value, route or role tuple, grep the whole repository for real callers, not only the owning module (`kt_my_work_providers`, `home_page`, `my-work`, `kt-procurement-home`, the ERPNext `Home` workspace, every `.kt-btn*` consumer).
9. **Design gates.** No UI row (Phase 4 onward) is Done before Gate HOME-G01A (the Home-scoped design system; closed 4 Oct 2026). The repo-wide Gate HOME-G01B is on hold and blocks nothing in Home. Server rows (Phases 2, 3) did not wait.
10. **Counts, labels and deadlines are server-made.** A row is not Done if the browser computes a count, a relative label, a due label or a Coming up entry (HOME §16).
11. **Disclosure and clearing are tested end to end** through the real endpoint as the real persona (Charles Mutiso, Brian Wafula, Amina Hassan, Dr Peter Kimani, Daniel Otieno, Jane Wanjiku, Naomi Chebet), with a negative case, including revoked scope.
12. **Narrow then broad.** Red then green on one test, the module tests once, then broaden only at a gate. Fidelity gates are due once per slice. Other modules' tests are re-run only when a dependency they use changed.
13. **Fixtures clean up.** Every test module registers a purge cleanup; browser-pass records count as test data. Build worlds once per module, not per test. Reseed the canonical world after a run that persists.
14. **Deferred scope stays deferred.** Analytics link, delivered-report destination, Contract Management and owner-document amendments stay `Blocked — owner` and count toward no readiness claim.
15. **Report exactly what was and was not run.** Never claim a result that was not observed. Flag any migrate, patch or seed need immediately and state dev's real state at the end of every task.
16. **Commits only when the owner asks, and only Home's own files.** The working tree carries other changes (OVS, CTX v1.1, Budget, Requisitions, Award, Evaluation); do not stage or revert them.
