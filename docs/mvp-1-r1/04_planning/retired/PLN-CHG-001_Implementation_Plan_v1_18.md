## 1. Governing approach

**Correct in place at the domain layer; re-port every screen from the v1.18 frames.** The v1.18 register (§1.3, §17.4) removes concepts (multi-year, Planning highest-advantage ranking, OCDS payload and per-item ocid, universal timing floors, synchronous publication inside approval, per-day reminder duplicates, `PLN_RESERVATION_RELEASE_FAILED`) and adds whole record families (stable Plan Item identity, financial basis and reuse, preparation signature, publication intent/attempts/acknowledgement, Treasury evidence, hold and withdrawal, per-proceeding actual events, evolving milestone notices, correction-request lifecycle, scope lock). That is a domain correction of the same size as the v1.12 cycle, not a greenfield rebuild: the proven envelope (`services/envelope.py`), AUTH-bound authorisation and evidence-chain segregation (`planning_authorization.py`), DPP entry copy/coverage mechanics, the one-`register()` page controllers, the screen cache and the two isolated test worlds all survive unchanged. Every one of the 21 screen families has a changed composition, so every screen is ported anew from its frame — no component reuse is declared, none is permitted without a plan amendment (AGENTS.md §6.6).

**Phase ordering follows the retrospectives.** Phases 1–2 are horizontal (sibling contracts and configuration first, because Planning cannot resolve a schedule profile, a decision-time affordability basis or an annual-budget denominator that does not exist; then the Planning domain module by module). Phases 3A–3H are vertical: one screen family at a time, API read model → screen → component tests → fidelity per frame → Playwright with per-role logins → live click-through, with the slice gate closing only on browser evidence. Seeds (Phase 4) and release evidence (Phase 5) close the cycle. Deletion of a superseded construct lands in the same phase as its replacement.

**Done means the §10.1 actors complete the journey in a browser.** Grace prepares, Julia certifies Digital Health (acting, 25 Nov 2026 10:30 EAT), Peter certifies HRMD, Mercy validates and consolidates, Josphat confirms funding, Charles signs and submits, Amina adopts and records Treasury submission, Daniel approves as Cabinet Secretary, the worker publishes and the acknowledgement activates Version 1; the later-Need scope-lock regression (§5.4.6) passes end to end against a Requisition and a published Tender.

Non-negotiables restated from AGENTS.md and KT-STD-001: business rules in services, never in Vue; every command re-checks responsibility, state and record version on the server; no `frappe.db.commit()` in request services; artboards ported class-for-class with machine-enforced fidelity; verdict before paint and Forbidden-as-data (§3A); inline errors never Message dialogs; the Python suite and Playwright never run concurrently on the site; TDD per behaviour; report only what was observed.

## 7. Risks

| Risk | Mitigation |
|---|---|
| The v1.18 domain change is the largest since v1.2; verification-last ordering has cost every module rebuild its biggest block of time | Phase 2 is split into eight module-sized sub-phases each with its own green suite; Phase 3 is vertical per family; slice gates close only on browser evidence. |
| Frozen-clock seeds (D19) interact with authority windows, intake close instants and the hourly scheduler | One clock helper in `kentender_core.seeds` used by NDS/PLN/REQ/TPR seeds; command-time checks tested at the window boundaries; the Playwright world pins its own instants. |
| Asynchronous publication introduces a worker into tests and seeds | `frappe.enqueue(..., now=frappe.flags.in_test)` runs inline under tests; the seed calls the worker function directly; RQ presence checked before Phase 4 ([[dropped-doctype-crash-and-queue-overload]]). |
| Stable-identity migration on live canonical data (`Plan Item` roots, publication rows) | Patches idempotent and dry-run on a copy of the canonical world before Phase 2a exit; `recover_orphaned_drawdowns` available for REQ links. |
| Decimal-string boundary vs float callers (REQ, Budget) | Planning accepts numbers from trusted service callers and strings from the API, normalising through `money.py`; contract tests pin both. |
| 90 frames with no machine ids; fidelity harness keyed on visible caption text | `frameScope` asserts uniqueness of every caption tag at spec start; a duplicated tag fails the suite loudly. |
| New doctype slugs colliding with Page routes | Slug-collision row in Phase 2a checks every new doctype's scrubbed name against `frappe.pages`. |
| Site's Fiscal Year overlap aborts the static Industry gate | Known (C18); record truthfully, run the Playwright half. |
| Cross-app fixture wipes (REQ `wipe_requisition_rows` is site-wide; Planning purge once deleted the canonical strategy) | Never run Python suites while a browser run is active; re-seed the canonical chain before Phase 4/5 browser work; purge guards assert fixture namespace. |
