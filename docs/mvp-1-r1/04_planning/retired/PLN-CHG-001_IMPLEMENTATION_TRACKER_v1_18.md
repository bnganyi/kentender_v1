## Tracker rules

1. Rows are permanent. Vocabulary: `Planned` / `In progress` / `Blocked` / `Partial` / `Done`. Reversed decisions are struck through in place.
2. `Done` requires the row's own evidence: a command with result counts, a named test, a diff, or a described browser observation with literal rendered strings. Never record a result that was not observed.
3. A row touching a file that still references a spec-prohibited concept is not `Done`. Prohibited here (v1.18 §16 and §17.4): a Procuring Entity selector or scope argument, a FY user grant, `User Permission` or a bare Frappe Role as authority, a task as permission, a client-only lifecycle guard; a mandatory Need on a direct requirement, a partial accepted-Need allocation, a fabricated residual source, a source-less item, a direct-source identity regenerated on copy; any Planning Budget reservation/release/revalidation/commitment call, `PLN_RESERVATION_RELEASE_FAILED`; an optional statutory route, Planner/HOPF equivalence, an extra HOPF approval state, a segregation reset across a correction chain; an editable submitted/approved/Active baseline, source-cohort expansion through correction, allowance reset on copy, a later source absorbed into a scope-locked item; implied coverage or fulfilment from plan inclusion or a Tender badge; universal method timing (`TENDERING_FLOOR`, `EVALUATION_CEILING`, `STANDSTILL_FLOOR`, `DEFAULT_*_BUFFER` constants), a missing-profile fallback, a hard-coded unverified legal threshold, a Plan-total reservation denominator, a reason-only waiver; `highest_advantage` ranking or a preference override, `Multi-year`/`multi_year_justification`, `ocds`/`ocid`, fabricated contracting-process ids; a user-entered actual, an unqualified item-level actual, missing-to-zero variance, later-forecast substitution, a per-day reminder key; synchronous external publication inside `approve_annual_plan`, blind retry/withdrawal on an unknown outcome, a fabricated acknowledgement, forced activation of held content; summary-only governance, a forced accordion/download prerequisite, delimiter-crammed facts, a prototype harness; disposal content; `Awaiting Finance` or `Confirmed` as a Plan status; `RecordRequisitionDrawdown`/`record_requisition_drawdown` (canonical is `AuthoriseRequisitionDrawdown`); `_stamp_design_clock` back-stamping; Stitch/Civic Ledger markup, `kt_cl_surface_registry.js` entries, sidebar work-queue entries, `showPeSwitcher: true`.
4. No row may introduce an alias, redirect, dual-write, compatibility shim or parallel legacy+new surface. Deletion lands in the same phase as its replacement.
5. Screens are built from `design/*.dc.html` frames class-for-class, one frame id per screen state; behaviour from §§9.6–9.7 and §11, never from frame content. Reusing a component for a state whose frame differs means re-porting it. Fixture data in a frame is exempt from fidelity; structure and geometry are not.
6. Slice gates (PLN18-G03..G10) close only on the plan's §4 slice gate: component tests, a fidelity assertion per frame, a Playwright spec on the D14 world with per-role logins (each §6 actor the slice serves plus outsider and nobody refused), absence assertions on refusal paths, first paint **and** one interactive re-render observed live, direct load / reload / back-forward incl. exact historical Version selection, a forced 500 state, the inline-error check, zero page-specific console errors, bundle hash changed, screenshots in `evidence/v1_18/`, the replaced v1.12 spec/components deleted.
7. Static and architecture guards are `Done` only when proven by a planted violation.
8. Fixture instants are pinned to §10.1/§13.1 (24 Nov–20 Dec 2026 EAT for Planning; seeds run under the frozen clock, D19), never `now`-relative; the Python suite and Playwright never run concurrently on the site (both move the intake flags). A row claiming a cross-app file is unaffected cites the specific file:line checked.
9. Diagnosis follows the KT-STD-001 §5 ladder; a full-suite run is never the first diagnostic step. A phase overrunning its target by half stops and records why.
10. Sibling contracts are built in the owning app with owning-app tests and tagged `[core]` `[budget]` `[nds]` `[req]` `[tpr]`; their specification amendments are follow-ups, not rows (D17).
11. Nothing seeded may carry `verification_status = Verified`; the canonical seed uses `Fixture-verified — not production law` (D16) and every screen/label that shows a rule shows that status.
