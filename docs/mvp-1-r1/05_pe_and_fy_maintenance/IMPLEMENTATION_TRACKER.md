## Tracker rules

1. Rows are permanent and use `Planned`, `In progress`, `Blocked`, `Done`.
2. `Done` requires the row's own evidence (a command, a test name, a diff, a screenshot description) — not "looks right."
3. If a touched file still references a concept this change unit prohibits (an editable global "current" flag, a Cartesian PE×FY generator, a client-only permission/lifecycle check, a selector treated as an authority grant — §19), the row that touches it is not Done.
4. No row may introduce a new alias, redirect, dual-write, compatibility shim, or parallel legacy+Vue maintenance screen. If one appears, treat it as a defect in that row, not a valid completion.
5. §12 (Claude Design contract) governs visual/content fidelity only. §1–11 and §13–20 govern behavior. A row implementing behavior from §12 content instead of §13+ is a defect, not a shortcut.
