## G0-005 — Backend/API gap report for v3 view-models

| v3 requirement | Existing backend readiness | Gap | Recommendation |
|---|---|---|---|
| ActivePlanBanner model (`has_active_plan`, plan label, actions) | High: `procurement_planning/api/landing.py` already exposes `current_plan` and action flags | Missing exact v3 contract envelope | Add thin adapter endpoint/service for explicit active-plan context |
| Unified Workbench item model across six queues and state transitions | Medium/Low: queue data exists but fragmented across approved-demands, planning-home queues, package workbench, releases | No single `work_item_id` lifecycle model; no unified queue aggregator | Add new server-side workbench aggregator endpoint and formatter |
| EvidenceDrawer business timeline + records (technical collapsed by default) | Medium: evidence APIs exist and package-level data exists | Output shape and entry points are not fully v3-oriented | Add thin adapter over existing evidence APIs; keep technical details permission-aware and collapsed |

### Conclusion
- Backend/control layer is reusable.
- Main gap is not business logic; it is a new v3 UI-facing aggregation/modeling layer.
