## 1. Purpose of This Seed Specification

This document defines the exact seed data required to make the procurement lifecycle feel like one connected journey from Strategy through Tender Management.

The previous rectification documents defined the journey architecture. This document defines the concrete seed records.

Cursor must use this as the source for:

1. master WORKS seed loader;
2. journey aggregation tests;
3. handoff card tests;
4. Procurement Home examples;
5. Procurement Journey View examples;
6. Tender/STD business-readiness tests;
7. cross-module evidence timeline tests;
8. negative fixture tests.

This document intentionally specifies concrete values. Cursor must not replace them with generic examples.

## 2. Seed Design Principles

| Principle ID | Principle | Meaning |
|---|---|---|
| SEED-PRIN-001 | One story only | The master journey must use District Hospital Renovation Works from Strategy through Tender. |
| SEED-PRIN-002 | Preserve business codes | Codes in this document must be used exactly. |
| SEED-PRIN-003 | Do not create disconnected examples | No Goods, Consultancy, or generic seeds should be used in the master journey. |
| SEED-PRIN-004 | End state must be explicit | The base seed ends at Tender Published with Addendum 01 issued and current publication snapshot V2. |
| SEED-PRIN-005 | Optional extended state must be controlled | Closing and Opening Readiness may be loaded only as an optional checkpoint. |
| SEED-PRIN-006 | Handoff cards are evidence/navigation | They do not replace authoritative source module records. |
| SEED-PRIN-007 | Business labels first | Journey and UI seeds must support business-readable labels before technical references. |
| SEED-PRIN-008 | Audit path must be deterministic | Evidence timeline order must be reproducible. |
| SEED-PRIN-009 | Negative fixtures must be separate | Broken/stale scenarios must not pollute the master happy path. |
| SEED-PRIN-010 | Reset must be safe | Reset may remove/recreate master seed records only. |

## 3. Seed End State Definition

### 3.1 Base Seed End State

The base master seed must end here:

```text
Tender Published
Addendum 01 Issued
Current publication snapshot V2
Submission window still open
Opening not yet conducted
Evaluation not started
Award not started
Contract not started
```

| Field | Value |
|---|---|
| current_stage_key | tender |
| current_stage_label | Tender Published |

| current_owner_module | Tender Management |
| next_action | Await tender closing / prepare bid opening readiness after submission deadline. |
| blocker_count | 0 |
| critical_blocker_count | 0 |

### 3.3 Optional Extended Checkpoint

If the existing TM2 seed already includes closing/opening readiness records, the loader may support:

```python
load_procurement_lifecycle_works_master(reset=True, checkpoint="OPENING_READY")
```

Optional extended checkpoint state:

```text
Tender Closed
Opening Readiness Available
Bid Opening not yet conducted
```

Journey current state for optional checkpoint:

| Field | Value |
|---|---|
| current_stage_key | opening |
| current_stage_label | Opening Ready |
| current_status_category | Ready for Handoff |
| current_owner_module | Tender Management / Bid Opening |
| next_action | Conduct bid opening session using the opening register rules. |
| blocker_count | 0 |
| critical_blocker_count | 0 |

### 3.4 Implementation Rule

If optional extended records are not available, do not invent closing/opening data. Mark Opening as:

```text
Not Started
```

or:

```text
Pending
```

according to status mapping.

When `reset=True`, remove/recreate only records where:

```text
is_master_seed = true
```

or business code is in this specification.

1. evidence links / journey steps;
2. handoff cards;
3. journey;
4. optional generated cross-module links;
5. TM2 seed records only if owned by this loader and marked master seed;
6. planning records;
7. demand records;
8. budget records;
9. strategy records.

If TM2 records are owned by a separate TM2 seed loader, call that loader's reset only if explicitly safe. Otherwise update/link existing TM2 records.
