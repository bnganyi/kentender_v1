# KenTender Frappe Context-Preserving Form Navigation Pattern

This document defines a concise cross-cutting solution for the recurring context-loss problem in KenTender modules such as Strategy, Demand Intake and Approval, Budget, and other workflow-heavy screens.

The issue appears whenever a user opens a create/edit form or so-called builder and suddenly feels like they are in a different app because the left menu, route context, module shell, and navigation behavior change.

The solution is not to eliminate all forms. Some create/edit/approval flows legitimately need Frappe document forms. The solution is to make those forms open inside a consistent KenTender module shell and preserve workspace context.

---

# 1. Problem Statement

Current behavior:

```text
User is in KenTender workspace
→ clicks New / Edit / Builder
→ route changes to a separate form or builder page
→ left menu changes
→ module context disappears
→ user must mentally re-orient
```

This creates the feeling that the user has entered a new application.

This is especially damaging in modules like:

- Strategy Management
- Demand Intake and Approval
- Budget and Funding
- Tender Management
- Procurement Planning

These modules are workflow workbenches. Users must remain oriented around the module, selected record, workflow state, and next action.

---

# 2. Core Principle

Forms may be separate routes, but they must not feel like separate apps.

Every create/edit/builder route should preserve:

- the same KenTender application shell
- the same global left navigation
- the same active module highlight
- a clear module breadcrumb
- a back-to-workbench action
- a sticky workflow/action header
- contextual record identity

---

# 3. Recommended Frappe Pattern

Use a shared custom page shell for KenTender module routes.

Instead of allowing each form or builder route to render as an isolated Frappe form experience, wrap it in a consistent shell:

```text
KenTender Shell
├── Global left navigation
├── Module breadcrumb/header
├── Sticky record/action header
└── Embedded form / builder / workspace content
```

This shell should be reused by Strategy, DIA, Budget, Tender, and other modules.

---

# 4. Route Pattern

Avoid disconnected routes such as:

```text
/app/strategic-plan/PE-MOH-SP-2026-0001
/app/demand/670ohgj3jt
/app/budget/BUDGET-MOH-2026
```

Prefer module-owned desk routes:

```text
/desk/strategy-management/plan/PE-MOH-SP-2026-0001
/desk/strategy-management/plan/PE-MOH-SP-2026-0001/edit
/desk/strategy-management/plan/PE-MOH-SP-2026-0001/structure

/desk/demand-intake-and-approval/demand/DIA-PE-MOH-2026-0001
/desk/demand-intake-and-approval/demand/DIA-PE-MOH-2026-0001/edit
/desk/demand-intake-and-approval/demand/DIA-PE-MOH-2026-0001/review

/desk/budget-and-funding/budget/BUDGET-MOH-2026
/desk/budget-and-funding/budget/BUDGET-MOH-2026/edit
/desk/budget-and-funding/budget/BUDGET-MOH-2026/builder
```

The route itself should communicate module ownership.

---

# 5. Left Navigation Rule

The global KenTender left menu must remain stable across:

- workspace pages
- selected record pages
- new forms
- edit forms
- builders
- approval/review pages

The active menu item should remain the parent module.

Examples:

```text
Strategy form open → Strategy Alignment remains active
Demand form open → Demand Intake & Approval remains active
Budget builder open → Budget & Funding remains active
Tender detail open → Tender Management remains active
```

Do not switch to a reduced form-specific side menu unless the user intentionally enters an admin/developer area.

---

# 6. Required Context Header

Every create/edit/builder page should have a consistent module context header.

Example for DIA:

```text
Demand Intake and Approval / DIA-PE-MOH-2026-0001
Draft · Goods · KES 200,000 · Required by 22 May 2026

[Back to Demand Workbench]                         [Save] [Submit for Approval]
```

Example for Strategy:

```text
Strategy Management / Ministry of Health Strategic Plan 2026–2030
Active · 2026–2030 · Version 1

[Back to Strategy Workbench]                       [Save] [Review Plan]
```

Example for Budget:

```text
Budget and Funding / BUDGET-MOH-2026
Approved · FY 2026 · KES

[Back to Budget Workbench]                         [Open Builder] [Save]
```

This prevents the user from feeling lost.

---

# 7. Builder Naming Rule

Avoid generic labels like:

```text
Open Builder
Budget Builder
Strategy Builder
```

These sound like separate applications.

Use task-oriented labels:

```text
Manage Structure
Manage Allocations
Edit Demand
Review Demand
Prepare Planning Handoff
```

Mapping:

```text
Strategy Builder → Manage Structure
Budget Builder → Manage Allocations
Demand Form → Edit Demand / Review Demand
Tender Builder → Manage Tender Documents / Prepare Publication
```

---

# 8. Prefer Drawers or Modals for Small Metadata Edits

Not every edit needs a full route.

Use drawers/modals for small metadata edits such as:

- edit plan name, entity, period
- edit budget name, fiscal year, currency
- edit demand priority or required-by date
- edit tender metadata

Use full pages only for substantial forms or workflows.

Recommended rule:

```text
Small metadata edit → drawer
Large structured form → context-preserving route
Workflow review/approval → context-preserving route
Builder-style multi-section editing → context-preserving route
```

---

# 9. Frappe Implementation Direction

In Frappe, implement this as a standard KenTender route shell rather than relying only on default DocType form routing.

Recommended approach:

1. Create custom desk pages for module workbenches.
2. Define module-owned routes under `/desk/<module-slug>/...`.
3. Keep the KenTender sidebar mounted for all module-owned routes.
4. Highlight the parent workspace item based on route prefix.
5. Embed or recreate the needed form sections inside the module page shell.
6. Use Frappe form APIs only where needed, but do not let the default form route own the user experience.
7. Add `Back to <Module> Workbench` as a first-class action, not a browser-back dependency.

---

# 10. Practical UI Shell Layout

Use this shell for all module-owned form/builder pages:

```text
┌────────────────────────────────────────────────────────────────────┐
│ Global KenTender top/browser area                                  │
├───────────────┬────────────────────────────────────────────────────┤
│ Global left   │ Module breadcrumb                                  │
│ navigation    │ Record title / route context                        │
│               │ Status ribbon                                      │
│               │ Sticky action bar                                  │
│               ├────────────────────────────────────────────────────┤
│               │ Form / builder / review content                    │
└───────────────┴────────────────────────────────────────────────────┘
```

The user should always know:

```text
Where am I?
Which module am I in?
Which record am I editing?
What state is it in?
How do I get back to the workbench?
What is the next action?
```

---

# 11. State Preservation Rule

When the user returns to the workbench, restore:

- selected queue
- search term
- filters
- selected record
- scroll position where practical
- active tab where practical

Example:

```text
Demand workbench: Approved queue selected
→ open DIA-PE-MOH-2026-0001/edit
→ save
→ Back to Demand Workbench
→ Approved queue still selected, same demand still selected
```

This is essential for case-management workflows.

---

# 12. Breadcrumb Rule

Use module-aware breadcrumbs, not generic document breadcrumbs.

Avoid:

```text
Demand / Test
Strategic Plan / Ministry of Health Strategic Plan 2026–2030
Budget / BUDGET-MOH-2026
```

Use:

```text
Demand Intake and Approval / DIA-PE-MOH-2026-0001 / Edit
Strategy Management / Ministry of Health Strategic Plan 2026–2030 / Manage Structure
Budget and Funding / BUDGET-MOH-2026 / Manage Allocations
```

This reinforces module context.

---

# 13. Action Placement Rule

Use a sticky action header on separate forms/builders.

Actions should be state-aware.

Example for Draft Demand:

```text
[Back to Demand Workbench]                  [Save] [Submit for Approval] [Cancel Demand]
```

Example for Submitted Demand:

```text
[Back to Demand Workbench]                  [Approve] [Return for Correction] [Reject]
```

Example for Draft Strategy Plan:

```text
[Back to Strategy Workbench]                [Save] [Submit Plan]
```

Do not bury primary workflow actions at the bottom of long forms.

---

# 14. Recommended Standard

All KenTender modules should follow this standard:

```text
Workbench page = browse, select, understand state, take next action
Form page = edit or review, but preserve module shell and context
Builder page = manage structured content, but preserve module shell and context
Default Frappe DocType form = admin fallback, not primary user workflow
```

---

# 15. Final Recommendation

Do not fight Frappe by eliminating forms entirely. Instead, control the user experience around them.

The cross-cutting fix is:

```text
Stable global left navigation
Module-owned routes
Context header
Sticky action bar
Back-to-workbench action
State restoration
Task-oriented builder names
Drawers for small edits
```

This will stop Strategy, DIA, Budget, and future modules from feeling like disconnected apps every time a user clicks New, Edit, Review, or Builder.
