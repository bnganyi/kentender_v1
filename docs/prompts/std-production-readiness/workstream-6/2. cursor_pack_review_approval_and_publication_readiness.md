# 1. Implementation Mandate

Cursor must implement the final legal gate from completed Tender STD Instance to published tender.

This is not a simple “publish button”. It is a controlled legal transition.

The implementation must ensure that a tender can be published only when:

1. Planning-to-Tender release lineage exists.
2. Tender STD binding exists.
3. STD Instance is complete and ready.
4. Bundle, DSM, DOM, DEM, and DCM exist and are current.
5. No generated output is stale.
6. Configuration snapshot exists before approval review.
7. Approval decision is complete.
8. Publication snapshot is created.
9. Published outputs and STD Instance are locked and immutable.
10. Evidence package is assembleable and exportable.
11. Post-publication changes require addendum or controlled reissue.

# 13. Publication Transaction Service

## Ticket PUB-0600 — Implement Publication Transaction Service

### Objective

Publish tender atomically without partial published state.

### Service Name

```text
PublicationTransactionService
```

### Required Method

```text
publishTender(tender_code, actor)
```

### Required Transaction Sequence

```text
Begin transaction
  1. Verify actor permission.
  2. Verify approval decision is Approved.
  3. Verify publication preconditions.
  4. Verify or assemble evidence package.
  5. Create Publication Snapshot.
  6. Mark Bundle Published.
  7. Mark DSM Published.
  8. Mark DOM Published.
  9. Mark DEM Published.
  10. Mark DCM Published.
  11. Mark STD Instance Published Locked.
  12. Mark Tender Published/Open.
  13. Record audit events.
Commit transaction
```

### Failure Behavior

| Failure Point | Required Behavior |
|---|---|
| readiness fails | abort; no state change |
| output stale | abort; no state change |
| snapshot creation fails | abort; no published state |
| evidence package fails | abort; no published state |
| output publish fails | rollback all |
| tender status update fails | rollback all |
| audit write fails | abort or critical failure according to audit policy; do not silently proceed |

### Acceptance Criteria

- Valid tender publishes atomically.
- Partial publication cannot occur.
- All outputs marked Published.
- STD Instance marked Published Locked.
- Tender marked Published/Open.
- Publication audited.
