## 2. Purpose

The purpose of this smoke test specification is to verify that the STD Template Governance and Lifecycle implementation works end to end before it is accepted as a production-readiness foundation.

The smoke test shall confirm that an STD template package can be imported, validated, submitted for approval, approved, activated, protected from mutation, used for tender creation eligibility, suspended, reinstated, superseded, retired, audited, snapshotted, and blocked from unauthorized or invalid actions.

This smoke test is not a full certification test. It is the minimum acceptance gate for the governance implementation delivered from the Complete Cursor Implementation Pack.

---

## 3. Smoke Test Principle

The smoke test shall implement this principle:

> A governed STD template version passes smoke testing only if lifecycle transitions, permissions, package-hash evidence, audit events, snapshots, tender-use eligibility, and mutation protections are all enforced server-side and visible through the admin UX.

The implementation fails smoke if it merely displays statuses without enforcing them.

---

## 4. Scope of Smoke Test

The smoke test covers:

1. role and fixture setup;
2. STD package import;
3. package validation pass/fail behavior;
4. submission for approval;
5. approval and separation-of-duty checks;
6. activation and tender-creation eligibility;
7. suspension and reinstatement;
8. supersession;
9. retirement and archival;
10. controlled package replacement;
11. protected mutation blocking;
12. delete blocking;
13. usage recording and usage lock;
14. audit event creation;
15. governance snapshot generation;
16. UI button visibility and dialogs;
17. permission failure behavior;
18. WORKS POC migration/seed verification.

---

## 5. Non-Scope

The smoke test shall not test:

1. bidder portal;
2. bid submission;
3. bid opening;
4. evaluation execution;
5. award;
6. contract execution;
7. final PDF generation;
8. public publication;
9. addenda lifecycle;
10. supplier clarification workflow;
11. planning-to-tender release implementation beyond checking template eligibility;
12. procurement officer guided tender configuration beyond active-template summary and eligibility.

If any of these are required for the smoke test to pass, that is scope drift.

7. Verify tender creation eligibility.

9. Confirm usage lock and mutation/delete blocking.
10. Generate governance snapshot.
11. Verify audit events.
12. Test suspension and reinstatement.

14. Supersede original version.
15. Retire replacement version in controlled test path.
16. Run negative permission and hash/staleness checks.
17. Verify admin UI and officer boundary.
18. Complete result table and issue log.

1. Log in as `std.importer@test.local` or administrator.

3. `latest_validation_status = Not Run`.
4. `allowed_for_tender_creation = 0`.
5. `package_hash` exists.
6. `package_hash_algorithm = SHA-256`.

8. `STD_TEMPLATE_IMPORTED` event exists.
9. Template is not eligible for tender creation.

### Evidence

Capture template detail and lifecycle event.

## 34. Pass Criteria

The STD governance smoke test passes only if:

1. roles and users are correctly configured;
2. valid package import works;
3. validation works and updates status;
4. invalid package validation blocks approval path;
5. validated package can be submitted;
6. submitted package can be approved by authorized approver;
7. approved package is not tender-eligible until activation;
8. activated package is tender-eligible;
9. non-active packages are not tender-eligible;
10. usage recording works;
11. used templates are locked against mutation/delete;
12. protected states block package mutation;
13. lifecycle events are written for all major actions;
14. governance snapshot JSON/hash is generated;
15. suspension/reinstatement works;
16. supersession works;
17. retirement works;
18. role permission negative tests pass;
19. stale hash/validation checks block unsafe actions;
20. officer cannot access governance internals;
21. existing WORKS POC template is governed;
22. no out-of-scope tender/bidder/evaluation/contract features are introduced.

---

## 35. Fail Criteria

The smoke test fails if any of the following occur:

1. package can be used for tender creation before activation;
2. validation failure can proceed to approval;
3. approval can occur with stale/mismatched package hash;
4. activation can occur without approval or hash consistency;
5. active/used package payload can be mutated;
6. used template can be deleted;
7. permissions rely only on hidden UI buttons and not server enforcement;
8. audit events are missing for lifecycle transitions;
9. governance snapshot cannot be generated;
10. Procurement Officer can edit or inspect raw package internals;
11. System Manager can mutate used template content;
12. Cursor introduced out-of-scope bidder/publication/evaluation/contract behavior.
