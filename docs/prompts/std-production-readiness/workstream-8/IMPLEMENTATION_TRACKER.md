# STD Engine — Admin and Officer UI Production Hardening — Implementation Tracker

## Goal

Deliver **production-grade, role-specific UI** for STD Administrator, Procurement Officer (and delegated assistant patterns where applicable), Approving Authority, and Auditor so users complete **business workflows** (library, release, tender configuration, works, outputs, readiness, approval, publication, evidence) without facing raw engine internals. **Backend action availability** must drive enable/disable/hide and denial copy; the UI must not treat Desk visibility or client-side role checks as authorization. **Done** means pack §23 Definition of Done is satisfied with **automated evidence**: targeted unit/component tests where appropriate, and **Playwright** (or an explicitly documented alternative) for user-visible flows per workspace quality gates.

### Hosting strategy (UI-HARD-0001) — **Hybrid**

| Layer | Location | Role |
|---|---|---|
| **Canonical TypeScript module tree** | [`apps/kentender_v1/frontend/src/modules/std-engine/`](../../../../frontend/src/modules/std-engine/README.md) | Pack §4 structure: per-workflow packages + `shared/` for action-availability, blockers, denials, status, api, types. Versioned beside **Playwright** (`kentender_v1` package). |
| **Primary Desk UX (today)** | `apps/kentender_procurement/.../public/js` (and related Desk pages) | Existing Frappe officer/admin flows; **no authorization** from menu visibility alone (`AGENTS.md`). |
| **Integration contract** | SEC-0410 / `frappe.call` from Desk bundles | UI-HARD-0100+ clients in `shared/` are imported or bundled into Desk **without duplicating** business rules in ad-hoc Desk JS. |

**Rationale:** The repo had no prior `frontend/src/modules/std-engine/` tree; creating it under **`kentender_v1`** keeps UI hardening artifacts next to Playwright and `typescript`, while Desk remains the runtime shell until/unless a separate SPA ships entire surfaces.

**Backend / API prerequisites:** Workstream-7 **SEC-0400 / SEC-0410** action availability service + whitelist APIs, **SEC-0900** audit/evidence query patterns, and publication/readiness services already in `kentender_procurement` are the **contracts** the UI client must call (`frappe.call` / REST as per root [`AGENTS.md`](../../../../../AGENTS.md)).

**UI validation:** Prefer **Playwright** under [`apps/kentender_v1/tests/ui/`](../../../../tests/ui/) with [`tests/ui/helpers/deskForm.ts`](../../../../tests/ui/helpers/deskForm.ts) and [`.cursor/rules/frappe-desk-playwright-patterns.mdc`](../../../../../../.cursor/rules/frappe-desk-playwright-patterns.mdc) when flows touch Frappe Desk. Use [`apps/kentender_v1/.env.ui`](../../../../.env.ui) for role users. Asset builds that touch Desk bundles: use [`scripts/bench-with-node.sh`](../../../../../../scripts/bench-with-node.sh) from bench root (see [`.cursor/rules/frappe-bench-node.mdc`](../../../../../../.cursor/rules/frappe-bench-node.mdc)).
