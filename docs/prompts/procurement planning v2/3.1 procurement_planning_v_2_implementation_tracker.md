## 0.1 Binding Operating Rule

Cursor must execute this tracker row by row.

Cursor may mark rows:

```text
Not Started
In Progress
Blocked
Implemented
Evidence Submitted
Rework Required
Deferred
Not Applicable
```

Cursor must not mark rows:

```text
Accepted
```

Only human review may mark a row **Accepted**.

A row is not complete until it contains:

```text
implementation evidence
test evidence
review notes where needed
```

## 1. Status Values

| Status | Meaning |
|---|---|
| Not Started | Work has not begun. |
| In Progress | Work has begun but is not complete. |
| Blocked | Work cannot continue without a decision, dependency, or repository clarification. |
| Implemented | Code/config/UI exists but evidence is incomplete or not reviewed. |
| Evidence Submitted | Required implementation and test evidence are attached. |
| Rework Required | Reviewer found a gap or implementation does not comply. |
| Accepted | Human reviewer accepted the row. Cursor may not set this. |
| Deferred | Explicitly deferred with reason, owner, and approval. |
| Not Applicable | Confirmed irrelevant after repository inventory, with reason. |

## 9. P5 — UI Implementation

## 9.0 Business-First Default UI Gate

This gate is binding for all P5 rows. P5 is not acceptable if the UI is technically complete but intimidating, overloaded, or dominated by internal lifecycle terminology.

Default Planning UI must show information in this order:

```text
1. Business summary
2. Current state in business language
3. Next action
4. Blockers, if any
5. Primary action
6. Secondary actions
7. Evidence link
8. Technical details only after explicit expansion or inside Evidence / Advanced / Audit views
```

Ordinary default views must not expose these before business-readable labels:

```text
raw lifecycle keys, for example package_release
raw lifecycle statuses, for example Handed Off
raw handoff codes, for example PLANINCL-MOH-2026-001 or PKGREL-MOH-2026-001
source_object_code / target_object_code labels
source_module / target_module labels when shown as raw fields
JSON field names
technical_refs_json
internal audit event IDs
internal DocType names where a business label exists
```

Business codes may appear where helpful, but only with user-facing labels and secondary visual weight.

Acceptable:

```text
Tender: TND-MOH-2026-001
Budget linked: BUD-MOH-INFRA-2026-001
```

Not acceptable as default primary content:

```text
Stage / status: package_release / Handed Off
Previous handoff: PLANINCL-MOH-2026-001
Next handoff: PKGREL-MOH-2026-001
Target object: TND-MOH-2026-001
```

Default handoff display must use **Business Mode**. Audit / Technical Mode may exist only through explicit Evidence, Advanced, Technical Details, or Audit View controls.

Default package queue filters must be only:

```text
All
My Work
Needs Review
Ready for Release
Released / Consumed
Blocked
```

Specialist filters must be inside **Advanced Filters**, not displayed as default chips.

P5 must be rejected if ordinary default views expose technical workflow traces instead of business-readable **What happened / What happens next / Evidence** panels.
