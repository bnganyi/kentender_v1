# Procurement Planning v2 — UI Specification and Wireframes

Patched the open **Procurement Planning v2 — UI Specification and Wireframes** canvas.

Key changes:

-   Added **Default Visibility Hierarchy and Progressive Disclosure Rules**.
-   Added a hard rule that ordinary screens must show:
    -   business summary
    -   current state
    -   next action
    -   blockers
    -   primary action
    -   evidence link
    -   technical details only after expansion
-   Defined **Business Mode** vs **Audit / Technical Mode** for handoff cards.
-   Explicitly banned raw default display of:
    -   package\_release
    -   PLANINCL-MOH-2026-001
    -   PKGREL-MOH-2026-001
    -   source\_object\_code
    -   target\_object\_code
    -   JSON field names
    -   audit IDs
-   Reduced default package filters to:
    -   All
    -   My Work
    -   Needs Review
    -   Ready for Release
    -   Released / Consumed
    -   Blocked
-   Moved specialist filters to **Advanced Filters**.
-   Rewrote the journey header and package overview to use business language.
-   Replaced technical workflow trace style with:
    -   **What happened**
    -   **What happens next**
    -   **Evidence**
-   Added UI smoke tests for technical leakage and compact filters.
-   Added acceptance criteria requiring default Planning UI to be business-readable and non-intimidating.
