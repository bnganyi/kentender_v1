## 1. Purpose of This Cursor Pack

This Cursor Implementation Pack translates the completed Tender Management v2 artifacts into a concrete implementation plan.

It is intentionally detailed. Cursor must not infer the architecture, UI behavior, state rules, data ownership, or legal controls from general procurement knowledge.

This pack must be treated as the implementation authority for:

1. module boundaries;
2. entity implementation order;
3. server-side services;

This pack is not optional guidance. It is a build contract.

### 3.1 KenTender bench — desk asset builds (Node)

KenTender work in this repository targets **Frappe Desk / `public/js` bundles** compiled via **bench**’s asset pipeline. Non-interactive shells (CI, Cursor agent terminals) often resolve **Node** to an older binary on `PATH`, so a bare **`bench` … `build`** invocation for assets is **forbidden** in tender-management prompt docs and agent instructions.

From the **bench root** (the directory that contains `./scripts/bench-with-node.sh` and `apps/`), compile procurement desk assets with:

```bash
./scripts/bench-with-node.sh build --app kentender_procurement
```

After Python or Desk hook changes, follow [`AGENTS.md`](../../../../../AGENTS.md): `bench --site kentender.midas.com clear-cache`, `bench restart` as needed, then hard-refresh the browser.

- [ ] Tender cannot publish without STD binding.
- [ ] Tender cannot publish without Bundle / DSM / DOM / DEM / DCM.
- [ ] Tender cannot publish without publication snapshot binding.
- [ ] Tender cannot define DSM/DOM/DEM/DCM-owned rules internally.
- [ ] Supplier submission checklist comes from DSM.
- [ ] Supplier BOQ quantity editing is impossible.
- [ ] Arithmetic correction is absent from submission and opening.
- [ ] Arithmetic correction appears only in Evaluation expected outcome.
- [ ] Contract handoff uses corrected evaluated BOQ total.
- [ ] Sealed bid access before opening is denied for Procurement Officer and System Administrator.
- [ ] Supplier isolation is enforced.
- [ ] Addendum 01 regenerates Bundle / DSM / DOM / DEM / DCM and revised publication snapshot.
- [ ] Late submission creates Late Submission Attempt, not Bid Submission.
- [ ] Backend action availability controls all legal actions.
- [ ] Direct API bypass is denied.
- [ ] UI workbench is implemented instead of raw DocType workflow.
- [ ] Supplier Portal uses DSM and locks BOQ structure.
- [ ] Audit reconstructs package → tender → STD instance → publication snapshot → addendum → submission → closing → opening → evaluation → contract.
- [ ] Legacy v1 document-as-source paths are blocked and audited.
