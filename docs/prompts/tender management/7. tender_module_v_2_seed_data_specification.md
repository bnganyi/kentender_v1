## 1. Scope and Non-Negotiable Seed Rules

This seed specification is not illustrative sample data. It is a deterministic test and implementation dataset.

It must support:

1. creation of a Works Open Tender from a released procurement package;
2. binding to the Works STD template version for **DOC 1 — Building and Associated Civil Engineering Works, Rev April 2022**;
3. creation of a tender-specific STD instance;
4. population of STD parameters;
5. generation of Bundle, DSM, DOM, DEM, and DCM outputs;
6. publication readiness validation;
7. publication approval and publication;
8. publication snapshot binding of exact output versions;
9. supplier access and participation;
10. clarifications;
11. addenda with explicit before/after diffs;
12. bid submission with document-level and BOQ-level data;
13. late submission rejection;
14. tender closing;
15. opening readiness handoff using DOM;
16. evaluation handoff using DEM;
17. contract handoff using DCM;
18. cancellation and retender edge cases;
19. complete audit reconstruction;
20. negative-path action-availability denials.

### 1.1 Seed Completeness Standard

This seed is complete only if the system can answer the following without inference.

| Question | Required Answer Source |
|---|---|
| Which procurement package created the tender? | `procurement_package_code` on Tender |
| Which STD version governed the tender? | Tender STD Binding |
| Which STD instance governed the published tender? | Tender STD Binding + Publication Snapshot |
| Which parameters populated the tender document? | STD parameter values |
| Which supplier submission items were required? | DSM — Document Submission Model |
| Which opening register fields were lawful to display? | DOM — Document Opening Model |
| Which evaluation rules applied? | DEM — Document Evaluation Model |
| Which contract values carried forward? | DCM — Document Contract Model |
| Which output versions were published? | Publication Snapshot |
| Which addendum changed what? | Addendum Impact Record with before/after diff |
| Why was a supplier submission accepted or rejected? | Submission validation payload + action availability result |
| Why was a late submission rejected? | Late Submission Attempt record |
| Which price goes to contract? | Evaluation result + contract handoff, not submitted uncorrected price |
| Can audit reconstruct the full lifecycle? | Tender Audit Events and Evidence Package |

### 1.2 Prohibited Seed Shortcuts

The seed must not use vague placeholders such as:

1. “documents complete” without listing required documents;
2. “evaluation model exists” without listing rules;
3. “contract carry-forward exists” without listing fields;
4. “audit event created” without event payload;
5. “BOQ complete” without item-level data;
6. “supplier submitted” without submission component detail;
7. “addendum issued” without before/after diff and impact analysis;
8. “published” without Bundle / DSM / DOM / DEM / DCM and publication snapshot references;
9. “permission denied” without action code and denial code.
