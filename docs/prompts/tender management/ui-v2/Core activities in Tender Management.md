**Core activities in Tender Management**

Tender Management is the module that turns a **released planning package** into a **controlled supplier-facing tender**. Planning hands over the approved package; Tender Management owns publication and all tender-stage changes before closing/opening. The Planning PRD already draws this boundary: Planning releases the package, while Tender Management consumes it and creates/prepares the tender.

| **Activity** | **What happens** |
| --- | --- |
| **Consume released package** | Receive the approved package from Procurement Planning and create/link the tender record. |
| **Prepare tender shell** | Confirm tender title, reference, procuring entity, method, category, value, lots, and source package. |
| **Attach tender documents** | Use the approved STD/document readiness output and supplier-facing tender documents. |
| **Set tender timetable** | Define publication date, clarification deadline, submission deadline, opening date, and key milestones. |
| **Configure supplier participation rules** | Define eligibility, bid security, mandatory documents, site visit/pre-bid meeting rules, and submission requirements. |
| **Review publication readiness** | Check that documents, dates, rules, lots, contacts, and approvals are complete before publication. |
| **Approve tender for publication** | Authorized user confirms the tender can go public. |
| **Publish tender** | Make the tender visible to suppliers/public portal and lock the publication snapshot. |
| **Manage clarifications** | Receive/respond to supplier questions before the clarification deadline. |
| **Issue addenda** | Publish formal changes to documents, dates, requirements, or clarifications, with approval and evidence. |
| **Manage tender status** | Track Draft, Ready for Publication, Published, Amended, Closing Soon, Closed, Cancelled, or Returned for Correction. |
| **Control pre-closing changes** | Prevent silent edits after publication; require addendum/correction workflow. |
| **Prepare closing handoff** | At deadline, lock supplier submissions and hand off to Tender Closing / Bid Opening. |
| **Record evidence** | Preserve publication evidence, document snapshots, clarifications, addenda, approvals, and audit trail. |

**What Tender Management does not do**

It should **not** approve demand, create procurement plans, create packages, evaluate bids, award contracts, or manually alter the released Planning baseline. It also should not let users quietly edit a published tender; any material change after publication must go through a formal addendum or cancellation/correction process.

**Simple lifecycle**

Released Planning Package  
→ Tender Shell  
→ Tender Document Setup  
→ Publication Readiness  
→ Publication Approval  
→ Published Tender  
→ Clarifications / Addenda  
→ Submission Deadline  
→ Tender Closed  
→ Bid Opening

The sensitive part is this: **Tender Management controls the legally visible version of the procurement opportunity.** Once published, the system must preserve exactly what suppliers saw, when they saw it, and what changed afterward.
