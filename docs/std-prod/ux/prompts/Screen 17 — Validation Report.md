Screen name:

Validation Report

User:

STD Administrator, Reviewer, Auditor

Purpose:

Show whether an STD version can proceed to review, approval, or activation.

Primary user goals:

\- See blockers, warnings, and informational findings.

\- Understand what must be fixed.

\- Jump to affected objects.

\- Run validation/smoke tests.

\- Export evidence for approval.

Required sections:

1\. Validation summary cards.

2\. Activation readiness status.

3\. Findings table.

4\. Smoke test results.

5\. Source traceability coverage.

6\. Render readiness.

7\. Approval readiness.

Findings table columns:

\- Severity

\- Finding code

\- Description

\- Affected object

\- Lifecycle gate

\- Suggested fix

\- Owner

\- Status

\- Actions

Required actions:

\- Run Validation

\- Run Smoke Tests

\- Open Affected Object

\- Assign Finding

\- Mark Resolved

\- Export Validation Report

Design constraints:

\- Blockers must be impossible to miss.

\- Show whether activation is allowed or blocked.
