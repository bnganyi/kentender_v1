Screen name:

STD Family Detail

User:

STD Administrator

Purpose:

Show one STD family and all versions belonging to it.

Primary user goals:

\- Understand the STD family identity.

\- See active, draft, superseded, and archived versions.

\- Create a new version.

\- Open a specific version.

\- View family-level source authority, applicability, and usage.

Required sections:

1\. Page header with STD family title, family code, category, source authority.

2\. Summary cards: active version, total versions, tenders using family, pending review.

3\. Family metadata panel.

4\. Versions table.

5\. Governance/usage summary.

6\. Actions area.

Required fields:

\- STD family title

\- Family code

\- Category

\- Source authority

\- Description

\- Procurement method coverage

\- Applicability coverage

\- Current active version

\- Created date

\- Last approved date

\- Review policy

\- Owner/maintainer

Versions table columns:

\- Version code

\- Lifecycle state

\- Package version

\- Source document

\- Approval status

\- Validation status

\- Activation date

\- Superseded by

\- Used in tenders

\- Actions

Required actions:

\- Create New Version

\- Import Version Package

\- Open Version

\- View Usage

\- View Audit Trail

\- Compare Versions

Design constraints:

\- Make it visually obvious that family is not the same thing as version.

\- Only active versions should show “Use in Tender.”

\- Superseded versions must remain readable.
