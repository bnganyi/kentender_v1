Screen name:

Parameter Dictionary

User:

STD Administrator, Procurement Configuration Designer

Purpose:

Manage all configurable STD parameters for one version.

Primary user goals:

\- See all tender-specific configurable fields.

\- Understand where each parameter appears.

\- Validate data type, options, dependencies, and requiredness.

\- Identify missing or broken parameter definitions.

Required sections:

1\. Header and parameter summary.

2\. Search/filter bar.

3\. Parameter table.

4\. Dependency/usage side panel.

5\. Validation issues panel.

Required table columns:

\- Parameter key

\- Label

\- Data type

\- Section

\- Applies to

\- Requiredness

\- Default value

\- Options/source

\- Validation rules

\- Used by render blocks

\- Status

\- Actions

Required filters:

\- Section

\- Data type

\- Required/optional

\- Lifecycle stage

\- Has dependencies

\- Has validation issues

\- Used in TDS

\- Used in SCC

\- Used in forms

\- Used in render blocks

Required actions:

\- Open Parameter

\- View Usage

\- View Rules

\- View Source Anchor

\- Add Parameter

\- Deprecate Parameter

\- Export Dictionary

Design constraints:

\- Parameters are configuration schema, not tender values.

\- Show dependency and downstream usage clearly.
