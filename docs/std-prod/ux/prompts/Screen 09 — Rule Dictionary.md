Screen name:

Rule Dictionary

User:

STD Administrator, Procurement Policy Designer, Legal Reviewer

Purpose:

Manage validation, activation, calculation, conditional display, and governance rules.

Primary user goals:

\- See all rules for an STD version.

\- Understand what each rule controls.

\- Identify blockers, warnings, and informational rules.

\- Verify legal/source basis.

Required sections:

1\. Rule summary cards.

2\. Search/filter bar.

3\. Rule table.

4\. Rule impact panel.

5\. Validation/smoke-test coverage panel.

Required table columns:

\- Rule key

\- Rule name

\- Rule type

\- Severity

\- Scope

\- Trigger stage

\- Affected object

\- Legal/source basis

\- Test coverage

\- Status

\- Actions

Rule types:

\- Validation

\- Conditional display

\- Activation

\- Calculation

\- Rendering

\- Governance

\- Addendum impact

Severity:

\- Info

\- Warning

\- Blocker

Required actions:

\- Open Rule

\- View Affected Fields

\- View Source

\- View Test

\- Add Rule

\- Disable where allowed

\- Export Rule Catalog

Design constraints:

\- Blocker rules must be visually prominent.

\- Every activation blocker should show what fixes it.
