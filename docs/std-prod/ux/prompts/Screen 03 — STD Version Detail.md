Screen name:

STD Version Detail

User:

STD Administrator, Legal Reviewer, Procurement Reviewer

Purpose:

Show the control center for one STD version.

Primary user goals:

\- Inspect lifecycle state and validation readiness.

\- Access sections, clauses, parameters, forms, rules, render blocks, and source traceability.

\- Submit/review/approve/activate/supersede the version.

\- Confirm whether the version can be legally used.

Required sections:

1\. Header with STD title, family code, version code, lifecycle badge.

2\. Activation readiness panel.

3\. Version metadata panel.

4\. Module status grid.

5\. Governance actions panel.

6\. Recent audit events.

7\. Linked source documents.

8\. Usage summary.

Required fields:

\- Version code

\- Package ID

\- Lifecycle state

\- Source authority

\- Source document hash

\- Package checksum

\- Created by

\- Created date

\- Last modified date

\- Approved by

\- Approval date

\- Activation date

\- Supersession status

\- Validation status

Module status grid:

\- Sections

\- Clauses

\- Parameters

\- Rules

\- Forms

\- Requirements schema

\- Price schedule schema

\- Evaluation schema

\- Render blocks

\- Smoke tests

\- Source traceability

Required actions:

\- Open Section Map

\- Open Parameter Dictionary

\- Open Rule Dictionary

\- Open Forms

\- Open Validation Report

\- Submit for Review

\- Approve

\- Activate

\- Suspend

\- Supersede

\- Archive

\- Export Package

Design constraints:

\- Active versions must appear immutable.

\- Show blockers clearly before activation.

\- Governance actions must be permission/state dependent.
