Screen name:

Rule Detail

User:

STD Administrator, Policy Designer, Reviewer

Purpose:

Inspect one rule and its logic, source basis, affected fields, and tests.

Primary user goals:

\- Understand the rule.

\- Confirm severity and trigger stage.

\- Confirm affected sections/fields/forms.

\- Review test cases.

\- See whether the rule blocks activation or tender publication.

Required sections:

1\. Rule identity.

2\. Logic definition.

3\. Trigger conditions.

4\. Affected objects.

5\. Source/legal basis.

6\. Test cases.

7\. Execution history.

8\. Audit history.

Required fields:

\- Rule key

\- Name

\- Description

\- Rule type

\- Severity

\- Scope

\- Trigger stage

\- Expression/condition

\- Error message

\- Suggested fix

\- Source anchor

\- Test coverage status

\- Active/inactive

Required actions:

\- Edit Draft Rule

\- Run Rule Test

\- View Affected Objects

\- View Source

\- Add Test Case

\- Compare Previous Version

Design constraints:

\- Rule logic must be readable by non-developers where possible.

\- Do not show raw code as the only explanation.
