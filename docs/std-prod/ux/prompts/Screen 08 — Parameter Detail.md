Screen name:

Parameter Detail

User:

STD Administrator, Configuration Designer

Purpose:

Inspect and configure one STD parameter.

Primary user goals:

\- Define field behavior.

\- Confirm validation rules.

\- Confirm source traceability.

\- See where the parameter is used.

Required sections:

1\. Parameter identity.

2\. Field definition.

3\. Validation rules.

4\. Options/defaults.

5\. Dependencies and conditional display.

6\. Source traceability.

7\. Usage map.

8\. Audit trail.

Required fields:

\- Parameter key

\- Label

\- Help text

\- Data type

\- Requiredness

\- Default value

\- Allowed values

\- Min/max

\- Pattern/format

\- Section binding

\- Render binding

\- Rule bindings

\- Source anchor

\- Lifecycle stage

\- Status

Required actions:

\- Save Draft

\- Add Validation Rule

\- Add Option

\- View Usage

\- View Source

\- Deprecate

\- Compare with Previous Version

Design constraints:

\- Changes to active versions are blocked.

\- Show whether parameter affects tender publication, supplier submission, evaluation, or contract formation.
