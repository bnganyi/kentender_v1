Screen name:

Section and Clause Map

User:

STD Administrator, Legal Reviewer

Purpose:

Manage the hierarchical section and clause structure of one STD version.

Primary user goals:

\- See all STD parts, sections, subsections, and clauses.

\- Distinguish locked, configurable, generated, and omitted sections.

\- Inspect clause source anchors and mutability.

\- Open a clause for detail review.

Required sections:

1\. Header with version identity and lifecycle state.

2\. Section tree panel.

3\. Clause table/detail area.

4\. Mutability legend.

5\. Validation issues panel.

6\. Clause detail drawer.

Required fields:

\- Section number

\- Section title

\- Parent section

\- Render order

\- Mutability type

\- Required/optional

\- Included/excluded

\- Source anchor

\- Clause count

\- Parameter count

\- Rule count

\- Validation status

Clause table columns:

\- Clause number

\- Clause title

\- Mutability

\- Source section/page

\- Text hash status

\- Parameters

\- Rules

\- Render status

\- Actions

Required actions:

\- Open Clause

\- View Source

\- View Parameters

\- View Rules

\- Mark Omitted where allowed

\- Reorder where allowed

\- Export Section Map

Design constraints:

\- Locked legal clauses must not appear editable.

\- Use a tree/detail pattern.

\- Make source and mutability visible on every row.
