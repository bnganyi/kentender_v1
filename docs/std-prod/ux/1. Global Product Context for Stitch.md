# Product: KenTender e-Procurement — STD Engine

Purpose:

KenTender digitizes official Standard Tender Documents used in public procurement. The STD Engine manages official STD template families, versions, clauses, parameters, rules, forms, validation, approvals, rendering, and tender binding.

There are two major UI areas:

1\. STD Administration — used by central/admin users to manage official STD template versions.

2\. Tender Configuration Wizard — used by procurement users to configure a tender from an active STD version.

Important distinction:

\- STD Family = the general template, e.g. “STD for Procurement of Information Technology”.

\- STD Version = a specific approved version, e.g. “KE-PPRA-IT-2022-04”.

\- Tender Configuration = a tender-specific instance created from an active STD version.

Non-negotiable governance rules:

\- Active STD versions are immutable.

\- Published tender bundles are immutable.

\- Locked legal sections such as ITT and GCC cannot be edited by tender users.

\- TDS, SCC, requirements, evaluation criteria, forms, and price schedules are controlled configuration areas.

\- Draft versions must pass validation, review, and approval before activation.

\- Post-publication changes require addendum/supersession.

\- Real tenders such as NSSF ERP are calibration examples, not master STD templates.

Design style:

Government-grade, clean, formal, audit-friendly, data-dense but readable. Avoid playful visuals. Prioritize clarity, traceability, status visibility, validation blockers, and review actions.

Ignore any side navigation in reference screenshots. Design only the main content area and page-level controls.
