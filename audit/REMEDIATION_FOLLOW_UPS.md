## Part A. Owner questions

### A1. Money and Budget

**A1.1 Storage for 18 integral digits (AUD-XC-129, RG-28, Blocked).** Documents (BUD §4.8 line 235, REQ §5.14, NDS §4.9, PLN §4.1) require at least 18 integral digits. Frappe `Currency` is decimal(21,9), so 12 integral digits, and Frappe reads it back as a binary float. Options: (a) keep the 12-digit ceiling with the typed overflow error (built; adequate while budgets stay below 1e12 KES) and amend the documents; (b) set `length`/`precision` on the Currency fields (widens storage only; reads stay float); (c) store money as decimal text with a generated DECIMAL column for sums, planned with Planning, Requisitions and Needs together. Recommended: (a) now, (c) if 18 digits are really needed. Planning's `money.parse_money` still allows 18 (`MAX_INTEGRAL_DIGITS`), so 13 to 18 digits pass the typed check and fail as a database error; cap Planning at 12 when this is decided. Needs a Requisition Item quantity decision too (Int). [WP2.3-3.5-3.6-budget 2; WP3.5-2.4-2.5 2; WP4R-L1 2; WP4R-L3 2]

**A1.2 KES and scale 2 (AUD-XC-133, RG-28, Blocked).** REQ §5.14 itself fixes KES scale 2; the Budget check/reserve contract carries scale 2 as a constant; Requisitions has `CURRENCY = "KES"`; the Tenders snapshot has constants. Options: (a) record KES scale 2 as a deliberate site constraint in BUD and REQ (recommended: the site is KES only); (b) make Requisitions, check/reserve and the Tenders snapshot currency-driven from `scale_for(currency)`, which changes approved contracts (REQ, BUD, TPR amendments first). Nothing changed. [WP4R-L3 2; WP3.5-2.4-2.5 3]

**A1.3 JSON floats at the editor boundary (BUD §4.8, BUD18-AC-051).** The document says float JSON fails before effects. The build accepts a float only when its shortest text is a plain decimal of at most 15 significant digits, because the Vue editor sends numbers. Options: keep and record in BUD (recommended until the editor sends strings), or make the editor send strings and refuse every float. `check_funding` and `reserve_funding` already refuse floats. [WP2.3-3.5-3.6-budget 1; WP4R-L3 doc follow-up]

**A1.4 Idempotency key mandatory on Budget governance commands (RG-16).** Principal commands require a key. Governance commands (save, submit, approve, close) still run without one when the client sends none (docstring of `budget_idempotency.py`). Making it mandatory needs the editor to always send one. Options: mandatory everywhere, or keep optional and say so in BUD. Recommended: mandatory once the editor is verified to always send a key. [WP4R-L3 3]

**A1.5 Contract Management has no module.** The Contract principal is allow-listed and tested directly but has no production caller; Budget cannot check the contract event or the "exact allocation". Recommended: when Contract Management is built, mint the principal only in its own gateway module, allow-list that module in `service_caller`, add the lineage rule (a contract converts only a reservation of its own tender) to BUD first, and add event validation. Until then leave the mint scan as is (RG-26). [WP1.2 1; WP4R-L3 4]

**A1.6 Who may call `revalidate_reservations` (Q1).** BUD §7 (line 358) lists it among the contract principal's calls; the build made it Budget-internal (Q1 default). Confirm the build or amend the text. [WP1.2; DOC_CHANGE_REQUESTS DCR-05]

**A1.7 Funding source on the requisition projection (BUD-BR-008).** Planning's projection carries no `funding_source`, so Requisitions cannot send one and Budget compares only when supplied. Options: Planning adds it and Requisitions passes it, then Budget can require it (recommended); or Budget treats the line's own source as authoritative. This is also AUD-REQ-009 (Wave 5). [WP3.1-3.3 1]

**A1.8 Close with an open successor (BUD-003); catalogue state of carried lines (BUD-010).** The document is silent on Close while a Draft or Submitted successor exists. Built: an open successor cannot be approved or submitted on a Closed Budget (`BUDGET_CLOSED`). Decide whether Close should be refused or should decline the successor. BUD-010 checks only new lines (carried lines keep their frozen identity so a retired department does not block revisions): confirm. "Available" is treated as usable; Draft and Retired funding sources are refused for new lines: confirm. [WP3.1-3.3 2, 3, 7]

**A1.9 Rounding of the required reservation (AUD-XC-132, Blocked).** PLN §5.5.3.1 defines required = percentage × eligible value and is silent on rounding; the code rounds half-up to the cent (so 30.00 qualifying reads as met at 29.997%).
