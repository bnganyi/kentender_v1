### REG-SOD-01 - HIGH - Legacy Tender Configurations module still approves and PUBLISHES a tender with no maker-checker and no Accounting Officer (CODE DEFECT, legacy surface)
**Evidence.**
- `kentender_procurement/tender_configurations/services/review_workspace.py:438-443` `approve_for_preview`: only `frappe.has_permission(doc=doc, ptype="write")`, then records `blob["approved_by"] = frappe.session.user` (`:479`). The submitter is recorded (`services/readiness.py:426` `blob["submitted_by"] = frappe.session.user`) and never compared.
- `services/publication_setup.py:562` `publish_tender`: `if not frappe.has_permission(doc=pub, ptype="write")` is the only authority; it then sets `pub.status = PUBLICATION_STATUS_PUBLISHED`, `published_by = frappe.session.user`, opens the bidder workspace and commits (`:597-641`). `return_publication_for_correction` (`:664`) likewise.
- Authority is a Frappe role: `tender_configuration.json` / `it_tender_publication_record.json` grant `write` to `Tender Manager` and `Planning Authority`; neither is a registry responsibility.
- Still live: `hooks.py:247` registers the `it-tender-configuration-dashboard` page; `modules.txt` lists the module; `tender_configurations/__init__.py:223,293` expose `approve_tender_configuration_for_preview` and `publish_tender` as `@frappe.whitelist()`.
**Rule.** TPR v0_17 §6 (publication is authorised only by the Accounting Officer; preparer/submitter cannot approve, TPR09-AC-035/039); AUTH-ADR-001 §5.5, §8 (no role-label authority).
**Repro sketch.** One user holding `Tender Manager`: `submit_tender_configuration_for_review`, `approve_tender_configuration_for_preview` (`confirm_preview_only=1`), `confirm_tender_package`, `publish_tender`: all pass; no second person and no Accounting Officer responsibility is ever consulted. (Test: `frappe.set_user(u_with_only_Tender_Manager)`; call the four endpoints in order.)
**Classification.** CODE DEFECT. The original sweep covered only the retired TM2 package (F11); this module was deferred as "legacy" (`FINDINGS.md` AUD-XC-143 note, `REMEDIATION_FOLLOW_UPS.md:46`) but it is a parallel publication path that bypasses the Tenders AO gate. Owner decision needed: retire the module (recommended, as with TM2) or put the AO/segregation gate on it.
