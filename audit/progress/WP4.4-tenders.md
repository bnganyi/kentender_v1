## Follow-ups
- F-1 (AUD-TND-002, Blocked, business decision). Unclear: TPR v0.17 §5.5(6) says that when the minimum period would be breached "the Tender cannot become Published until a lawful revised deadline is issued in the same immutable publication package", but §7 has no command that does this, and the package digest covers the deadline, so a revised deadline changes the digest the already-confirmed channels were attested against. Options: (A) a governed "Revise publication deadline" command by the Head of Procurement Function that issues a revised deadline inside the same Publication (new digest, previously confirmed channels must be re-confirmed against it); (B) AO withdraws authorisation even after confirmations (changes TPR AC-055, which allows withdrawal only with none confirmed) and the Tender returns to Approved for reopen; (C) refuse and keep current behaviour (Tender stays Publication authorised). Recommended default: A, "revise the deadline in the same package" (keeps the publication record, never asks the HoPF to attest a false availability time). Done instead: nothing; no code changed; the existing test's workaround (re-confirm with an earlier `available_at`) is still the only exit and invites false attestation, so this stays High until decided.
- F-2 (AUD-TND-001, document gap). After the period closes an addendum still Awaiting publication confirmation can never complete and its tasks are cancelled by the close, but the addendum has no terminal status (Draft / Returned / Awaiting issue / Awaiting publication confirmation / Issued / Discarded). Options: add a "Lapsed" status set by the close, or leave it Awaiting and show it as not effective. Recommended: add "Lapsed" at the next TPR version. Done instead: refuse the effect; the addendum stays Awaiting and the screen offers no action.
- F-3 (AUD-TND-008). `tenders/services/opening_seam.py::processing_actors` (the "who processed this Tender" list handed to Bid Opening for conflict checks) still lists only prepared_by / submitted_by / approved_by / authorised_by, not draft editors. Same concept as TND-008; changing it alters a cross-module contract, so it was left. Recommended: add `draft_commands.draft_editors(tender)` to that set once Bid Opening confirms it wants editors treated as processors.
- F-4 (AUD-TND-013). A genuine two-connection StartTender race was not run; the loser branch is covered by a stale-snapshot simulation. Worth one real concurrent probe (two requests, same handoff, different keys) on the test server.
- F-5 (AUD-TND-005). The audit commit happens in the three endpoints; a direct service caller (seed, job) that hits the conflict still loses the event if its own transaction rolls back. No such caller exists today.
