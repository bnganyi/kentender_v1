## Follow-ups

- F1 (AUD-REQ-002, secondary). REQ §7.1 allows "Submit to Procurement" from Draft only for a "Head of User Department preparing directly". Today `read.py` offers it on a Draft to any lead Head who is not a lead Author, and the command accepts it, so a different Head can certify an Author's Draft without the departmental task. Options: (a) keep (current, documented in the editor offer); (b) require `prepared_by == actor` with Head capacity on the Draft path, so every Author-prepared Draft goes through Send for approval. Recommended default: (b), as §7.1 states it. Not changed: it alters who is offered what on the Draft screen and the seed profiles; I implemented only the confirmed Author-turned-Head block.
- F2 (AUD-REQ-003). The brief said implement only preparer is not authoriser. REQ is silent on whether the sender (the Author who sent the Draft for approval) or the certifying Head may also authorise. Options: block the sender too (the sender is now recorded in `sent_for_approval_by`); block neither. Recommended default: block the sender too, since REQ19-AC-045 says no self-authorisation. The certifying Head is already blocked (`submitted_by`). Not changed.
- F3 (AUD-REQ-004). The finding lists PLN_ITEM_AUTHORISATION_HELD as an expected refusal on submission from the approval task. REQ §7.2 says a correction hold blocks new authorisation only and existing Draft work may continue, and the Draft path's `lock()` never checked the hold, so I gave the approval-task path exactly the Draft path's rechecks (eligibility, nine compatibility checks, Blocking findings, digest). The hold is still refused at authorisation. If the owner wants the hold to stop routing, it must be added to the one `lifecycle.recheck` for both paths.
- F4 (AUD-REQ-006). Acceptance, related-service, supporting-material and item rows have no "recorded functional reason" column, so the §6.3 escape ("or equivalent" plus a recorded functional reason) cannot be met there: only brand-free wording passes. Options: add a reason column to those rows, or accept brand-free-only for them. Recommended default: accept brand-free-only (what is implemented); technical rows keep the existing equivalent-plus-reason rule.
- F5 (AUD-REQ-005). An `All items` row is judged against every item category in the package, so a mixed Laptop and Monitor package cannot carry a Monitor-only characteristic as `All items`; it must be scoped to the Monitor item. Recommended default: keep (matches §6.3). The editor's Add dialog should offer only characteristics whose `applies_to` includes the chosen category (the catalogue already sends `applies_to`); not changed here (Vue), see Needs browser check.
- F6 (AUD-XC-107, shared). `tenders/services/envelope.py::locked` (line ~94) has the same lock-then-plain-read pattern as the two I fixed. That file is in the Tenders area another agent is editing, so I did not touch it. Recommended: apply the same one-line `for_update=True` there.
- F7 (AUD-XC-107, shared). Changing `envelope.locked` in Planning and Requisitions affects every command in those two apps (they now read the latest committed row after the lock). Planning `test_plan_requisition` (38) and all Requisitions modules passed; the lead's wave sweep should include the other Planning command suites (workbench, governance, publication, finance, DPP).
