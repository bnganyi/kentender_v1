## Follow-ups
1. BUD §4.8 / BUD18-AC-051 say float JSON fails before effects. The editor sends numbers (`<input type=number>`), so `parse_money` accepts a float only when its shortest text is a plain decimal of at most 15 significant digits (what the user typed keeps its exact meaning) and refuses the rest. Options: keep (recommended until the editor sends strings), or make the editor send decimal strings and refuse every float. `check_funding`/`reserve_funding` already refuse floats (Requisitions sends strings). Did: the lenient rule above.
2. AUD-XC-129 storage. Frappe `Currency` is decimal(21,9) (12 integral digits) and Frappe reads it back as a binary float, so the documents' 18 integral digits cannot round-trip through `get_doc`/`save` however wide the column is. Options: (a) leave the 12-digit ceiling with the typed overflow error (done; adequate while budgets stay below 1e12 KES); (b) set `length`/`precision` on the Currency fields in the doctype JSON (migrate then alters the 5 small Budget tables, low risk) - this only widens storage, reads stay float; (c) recommended if 18 digits are really required: store money as decimal text (Data/varchar with a generated DECIMAL column for sums) behind the money helper, planned with Planning/Requisitions/Needs together (BUD18-XD-002). Did: (a). Owner decision needed.
3. BUD §4.8 CurrencyBasis is also meant to be retained on the Budget root (`currency_basis_reference`) and on approved Versions. Added only the read-time basis (`currency_basis`); no schema field was added (needs a schema change and a controlled backfill of existing Budgets). Recommended: add a read-only, set-once field written at registration and copy it to each Version.
4. `create_budget_successor_version` carries no `expected_modified` (it creates a Version, there is no stamp to compare; the at-most-one-open-successor lock is its guard). The document's "every write requires the expected record version" may want an explicit exception for creation. Not changed.
5. Read models still use `flt()` for display only (analytics provider recomputation, `_reservation_ledger_sums`, funding activity list, the editor's client-side preview with a 0.005 display tolerance). No decision reads them. Converting them is cosmetic; listed so the BUD18-XD-002 storage/arithmetic scan can find them.
6. WP3.3's patch `bud_chg_001_v1_12_commitment_contract_unique_per_reservation` dropped the table-wide unique index on `Procurement Commitment.contract`, but the doctype JSON still said `unique: 1`, so any later schema sync of the doctype (mine, when its `modified` changed) re-created it and un-did the patch. Fixed here: `contract` is `unique: 0` in the JSON; the composite `uq_commitment_contract_reservation` (patch) is the only unique key. Verified on the test site after migrate (indexes listed).
7. Idempotent replays: the payload digest includes `expected_modified`, so a replay must re-send the identical payload including the stamp (the Vue client does; the test helper `stamped` stamps at call time, so replay tests now build the payload once).
8. The ledger event and submission attempt are append-only for every user, and for the service for updates; a delete inside any open Budget window is allowed (a window cannot tell the service from the clean-up helper). No service deletes either; only `purge_doc`/`maintenance_write` (dev/test sites, never in a request) do.
9. Dead `frappe.flags.allow_budget_audit_purge` assignments remain in several seeds/tests and `canonical.py`; Budget no longer reads that flag (clean-up goes through `purge_doc`). Harmless; remove in a later tidy.
10. Other apps' tests that mutate Budget amounts with `frappe.db.set_value(...)` (Planning governance/publication tests) bypass controllers by design of Frappe and are not covered by the guard; they are test-only.
11. An unrelated pre-existing hazard seen on the test site: 76 leftover Procurement Budget rows (from earlier runs by other sessions) collide with the random test fiscal-year slots. `_BudgetLifecycleTestBase._fresh_fy` now skips a year that already has a Fiscal Year or a Budget. Leftover rows were not deleted (shared database).
