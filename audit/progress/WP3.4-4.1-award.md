## Follow-ups
1. Owner to confirm the Q3 default, which is implemented as a server refusal. The person who prepared or signed the opinion for a case (any opinion, any cycle; `author` or `signed_by`) cannot record the Award, No award, Return or correction decision. The person who recorded any decision on the case cannot prepare, sign or save the opinion. Options: keep it; narrow it to the same cycle only; or drop it for sites with a single HOP/AO. Recommended default: keep it. Side effect: on a site where one person holds both offices, the case dead-ends for that person.
2. Evaluation seam (not edited, another agent is working there). `bid_evaluation.services.correction.return_report` accepts only the recorded recipient (`delivery.recipient_user != user` gives Not found). For AUD-AWD-011, Award works around this by passing the recorded recipient as `user` when that person no longer holds HOP. The successor is named in the comment and in Award's audit, but Evaluation's own `returned_by` shows the former HOP. Proper fix for the Evaluation owner: accept the current HOP holder (or take an `acting_for_recipient` argument) and record the real actor.
3. AUD-AWD-003 residual, needs an owner decision. For a manually recorded external order (Board or court notice, entered through Record restriction) the operative release evidence is still free text, because Award has no owner event to compare it with. Options: a structured authority reference plus a second person; or require the originating authority's release reference to match a field recorded at hold time. Recommended default: leave as is and rely on the audit trail until the owner defines "verifiable". The other "Owner correction confirmed" issue types (Rules and notice audience, Delivery, Service failure, Validity) also still accept free text. Only Funding was in the finding.
4. Budget published read. Award uses the already-published `kentender_budget.services.budget_downstream_contracts.get_funding_lineage`, so no Budget code changed. Checked on the test site: it answers for the Accounting Officer, the Head of Procurement and Administrator on the canonical Award tenders. It depends on the caller's Budget version read scope. If the Budget lock/approval work narrows that scope for AO or HOP, Award fails closed (funding unreadable) rather than passing. Recommend Budget publish the dedicated evaluation-funding contract that Evaluation already says is owed (FU-EVL-06).
5. After Contracting converts a reservation into a commitment, the reservation's `remaining_amount` falls. A corrected award recorded after a commitment (successor cycle) would then see a shortfall against the evaluated amount. Needs a rule on whether committed amounts count as available for the same award. Not changed.
6. `reads.record` (the `award_supported` flag) now makes one Budget read per page load, because it reuses `positive_guards`. If this is slow in the browser, add a short per-request cache.
7. Evaluation and registry side of AUD-AWD-001: the Accounting Officer or HOP can still be appointed an evaluation member or chair, and the report signers are never compared with the deciding AO. The registry `sod_tags` for AO and HOP carry no evaluation or opinion tag. This belongs to Evaluation appointment rules and the Core registry, not Award. Owner decision needed on the incompatibility rule.
8. Latent pattern: `guards.open_case` and `guards.positive` use `g = g or Guards()`, and an empty `Guards` is falsy. Harmless today (callers pass `None`), but it will drop a caller-supplied empty collector. I only fixed it in the new `guards.funding`.
9. Test environment (not mine). Budget and Planning test runs leave about 20 enabled HOP and AO assignments on the test site (`bud.hopfsp.*`, `bud.ovs.*`, `plnt.*`). Award's `first_holder` then picks one of them. This makes 6 existing Award tests fail on `first_holder` identity (see Commands run). Separately, `test_awd_integration` fails in `tearDownModule` because assignment deletion is now guarded (`COMMAND_ONLY_DELETE`); it needs `purge_doc`, which another agent has already begun applying in `test_home_provider.py`.
10. The UI error text for `AWD_STATUS_UNAVAILABLE` is the generic "tender status could not be confirmed". For funding the refusal carries `detail.check == "funding"` and `detail.reason`. The Award screen should show the detail reason (browser check).
