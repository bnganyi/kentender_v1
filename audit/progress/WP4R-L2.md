## Follow-ups
1. **RG-21 (Blocked, confirmed).** Reference candidates are probed with `select ... for update` on absent keys (`kentender_core/utils/series.py::next_free_reference`). Under REPEATABLE READ that takes a gap lock; two creators with different prefixes whose candidates fall in the same gap both hold it, then each insert waits for the other: MariaDB error 1213 rolls one request back. Reproduced with two connections on a scratch table. Callers (other lanes' files): Planning `references.py:75/:128`, Requisitions `references.py:66`, Tenders `references.py:56/:63`, Needs `lifecycle.py:411`. Options: (A) allocate from the atomic `tabSeries` counter (`raise_series_to` already exists) and stop reusing purged numbers - a numbering behaviour change the owner/spec must accept; (B) one named lock per doctype (not per prefix) held to commit, so two creators of the same doctype never interleave - no behaviour change, but the lock lifetime has to be checked at every caller; (C) READ COMMITTED for the allocating transactions - not settable inside an open transaction. Recommended default: (B). Did nothing.
2. **RG-39 (Blocked).** `authorise_record(purpose=COMMAND)` admits a technical principal that holds an assignment, and `sod_tags` have no consumer. Denying technical principals on commands there changes who can act for Award, Evaluation, Opening, Planning and the canonical/Playwright personas that hold System Manager and a business role together. Options: (a) deny technical principals on every command and re-seed personas without System Manager; (b) deny only when the assignment was granted before the technical role (needs a grant date comparison); (c) leave as is and keep Award's own exclusion. Recommended: (a) after the personas are checked. Nothing changed.
3. **RG-12 owner question.** Guest registration (`ktsm_register`) still writes a Supplier and a Draft profile with `ignore_permissions` for an unauthenticated caller and now records no contact e-mail at all (there is no profile field for it and the User is not created).
