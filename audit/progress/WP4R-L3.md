## Follow-ups

1. **RG-14 spec reading.** "Prepared" is every officer who ran an editing command on the requisition (Requisition Command Journal), and a Head may certify directly only if they prepared in the Head capacity. After the lead department is changed, the new lead's Head therefore certifies through the department approval task (a lead-department Author sends it) rather than directly. If the owner wants the new lead Head to certify directly, say so and the rule needs one more clause. REQ v1.14 section 7.3 bullet 1 should say "prepared or edited" (document follow-up).
2. **RG-28 / XC-129 / XC-133 blocked.** REQ v1.14 section 5.14 itself fixes money at KES, scale 2, 18 integral digits, and the Budget check/reserve contract carries scale 2 as a constant. Taking scale and currency from `scale_for(currency)` therefore changes an approved contract, not just code. Options: (a) keep KES scale 2 and record it as a deliberate site constraint in BUD and REQ (recommended: the site is KES only); (b) make Requisitions, check/reserve and the Tenders snapshot currency-driven (REQ, BUD and TPR amendments first). XC-129 needs the storage-type decision (12 stored integral digits against 18 required) first. Nothing changed.
3. **RG-16 optional key.** Governance commands still run without a key when the client sends none (BUD v1.9 section 9.3 "Commands without a key run as before"); only the principal commands require one. Making the key mandatory for governance commands needs a Vue change (the editor must always send one) and is an owner/BUD question.
4. **RG-26 runtime restriction.** Minting is restricted by an import/syntax-tree test, not at runtime. A runtime check on the calling module is possible but brittle across tests and seeds; recommended default: leave it until Contract Management exists, then give it its own gateway module and allow-list that module in `service_caller`. The Contract lineage rule (a contract may convert only a reservation belonging to its own tender) must be written into BUD before that caller is built.
5. **Owner decisions still pending:** RG-35 (do TM2 mentions in docs/archive and the sidebar label "Tender Management" count against D1), RG-37 (is redelivery of award notices by a Technical Operator "correspondence"), RG-38 (is Addendum issue a maker-checker action), RG-39 (technical principals denied on commands in `authorise_record`, `sod_tags` consumers, later System Manager grants). Not guessed.

They break `award.tests.test_awd_decision::test_no_award_follow_up` (the task is assigned to the first HOPF holder) and lane 2 saw 16 leftover Funding Reservation rows. Not purged here because another worker's run may own some of them.
7. **Opening/Proceedings authorise-before-replay.** Both claim the key first and bind it to the actor (the payload hash includes the actor), but Opening's commands authorise inside the command body, so the same actor who has since lost standing could be answered a recorded result. Evaluation already records standing with the key; Opening could do the same. Low; not done.
8. **Legacy `Command recorded` rows** in Budget Audit Event stay as they are (read by nothing now). A retry with a key recorded before the change re-runs the command; the state guards make the governance commands safe to repeat.
